ShogunAgent は「記憶」ではなく「仕事の状態」を売れ

ShogunAgent should sell “state of work,” not “memory”

AI エージェント向けメモリ API は飽和した。空いているのは、人・プロジェクト・コミットメント・オープンループを provenance と confidence 付きで推定し、L1/L2/L3 の承認階層ごしに複数エージェントへ貸し出す層である。ShogunAI の「難しい部分」の 70% 以上はそこへそのまま持ち越せる。

The agent-memory API market is saturated. The open space is a layer that infers people, projects, commitments and open loops with provenance and confidence on every fact, and lends that state to many agents through L1/L2/L3 approval tiers. More than 70% of ShogunAI’s hard parts carry over directly.

1. 競合は「ユーザーの事実を覚える API」で飽和し、「仕事の状態」は空白

1. Competitors saturate “remember the user’s facts”; “state of work” is empty

開発者向けメモリ API はこの 18 か月で API 形状・価格・配布経路がすべて収斂した。形状は「add/ingest → 非同期抽出 → search/retrieve → 任意で graph/profile」、配布は「Apache-2.0/MIT の OSS コア＋マネージドクラウド＋MCP サーバー」、価格は「Free → $19〜20 → $100〜400 → Enterprise」。計量単位だけがばらつく：トークン（supermemory $0.005/1K SM tokens）、バイト（Zep 1 credit/350 bytes、検索無料）、リクエスト（Mem0 Starter $19、Pro $249）、アクティブエージェント（Letta $0.10/agent/月）。supermemory · Zep · Mem0 · Letta

資金は Mem0 の $24M Series A（TechCrunch）と「学習型メモリ」を掲げて $98M で登場した Engram（Pulse 2.0）を除けばシード規模で、あるトラッカーはこのカテゴリを 14 件・$124M・中央値 $5.88M と数え、メモリは 2026 Q2 のエージェント AI 投資の約 1%（agentmarketcap）。投資家の総意は「ラボがパーソナライズ記憶を吸収する」。OpenAI は 2026-06-04 に背景プロセス "Dreaming"（OpenAI）、Anthropic は Managed Agents の memory（2026-04-23 公開ベータ）と "dreaming"（2026-05-06）、AWS は長期記憶を $0.75/1,000 記録/月＋$0.50/1,000 取得で売る（AWS）。ハイパースケーラーの価格が保存単価の床であり、第三者が勝てるのは抽出品質・時間推論・可搬性・推論（inference）に限られる。

Developer memory APIs converged over the last 18 months on shape, price and distribution. Shape: add/ingest → async extraction → search/retrieve → optional graph/profile. Distribution: Apache-2.0/MIT open core + managed cloud + MCP server. Price: Free → $19–20 → $100–400 → Enterprise. Only the metering unit varies: tokens (supermemory $0.005/1K SM tokens), bytes (Zep 1 credit per 350 bytes, retrieval free), requests (Mem0 Starter $19, Pro $249), active agents (Letta $0.10/agent/month). supermemory · Zep · Mem0 · Letta

Apart from Mem0’s $24M Series A (TechCrunch) and Engram’s $98M launch as “learning memory” (Pulse 2.0), funding is seed-scale: one tracker counts 14 deals, $124M, $5.88M median, and memory is about 1% of Q2 2026 agentic capital (agentmarketcap). Investor consensus: the labs absorb personalization memory. OpenAI shipped background “Dreaming” on 2026-06-04 (OpenAI); Anthropic shipped Managed Agents memory (public beta 2026-04-23) and “dreaming” (2026-05-06); AWS sells long-term memory at $0.75 per 1,000 records/month plus $0.50 per 1,000 retrievals (AWS). Hyperscaler prices are the floor for storage; a third party wins only on extraction quality, temporal reasoning, portability, or inference.

空いている三つの交差点

Three open intersections

1

推定された仕事の状態

Inferred state of work

メールやカレンダーからオープンループやコミットメントを推定する専用製品は無い。最も近い Microsoft 365 Copilot の「communication memory」は M365 テナントに閉じている。

No product infers open loops and commitments from mail and calendar. The closest, Microsoft 365 Copilot “communication memory,” is locked to the M365 tenant.

2

複数エージェント＋人の共有状態

Shared state across agents and humans

Memory Store は $500K シード、ByteRover はプレシード、Tabnine は機能にとどまる。Futurum は「共有メモリが 2027 年に RFP 標準要件になるか」を問う段階。

Memory Store is a $500K seed, ByteRover pre-seed, Tabnine a feature. Futurum asks whether shared memory becomes a standard RFP item in 2027.

3

本当のローカルファースト／ゼロ保持

True local-first / zero retention

資金調達済みベンダーは全てクラウドファースト。ローカルは MemPalace や SuperLocalMemory など OSS 趣味プロジェクトが担う。Limitless は Meta に買収、Rewind は停止、Graphlit は縮小、Khoj Cloud は終了。

Every funded vendor is cloud-first; local is left to hobby OSS such as MemPalace and SuperLocalMemory. Limitless sold to Meta, Rewind stopped capture, Graphlit wound down, Khoj Cloud closed.

「生の記録」に消費者は払わなかったが、生の記録を構造化された状態に変える推論層は誰も商用化していない。a16z は「エージェントはビジネス文脈の欠如で失敗する」と書き（a16z）、Deep Feed はメモリを「型付きビジネス知識／証明付き学習／セッション状態／ユーザー個人化」の 4 製品に分け、最後のものだけがラボにネイティブ提供されると整理した（The Deep Feed）。ShogunAgent は「型付きビジネス知識」側に立つべきで、比較対象は Mem0 ではなく Jedify（$24M Series A）や Interloom（$16.5M シード）である。

需要側の信号は間接的だが強い。LangChain の調査（1,340 回答）では 57.3% がエージェントを本番運用し、1 万人超企業の自由記述は「大規模な文脈管理の継続的な困難」を挙げる（LangChain）。Claude Code のランレート収益は 2026 年 2 月に $2.5B を超え（Simon Willison）、権限プロンプトは 93% が承認される（NeuralTrust）。承認 UX は壊れており、「ローカル可逆は即実行、外部送信だけ専用ボタン」という L1/L2/L3 はそこに応える。

Consumers did not pay for raw recordings, but nobody has commercialized the inference layer that turns raw records into structured state. a16z writes that agents fail for lack of business context (a16z); The Deep Feed splits memory into four products (typed business knowledge, verified learning, session state, user personalization) and notes only the last is natively supplied by labs (The Deep Feed). ShogunAgent belongs on the typed-business-knowledge side; its comparables are Jedify ($24M Series A) and Interloom ($16.5M seed), not Mem0.

Demand signals are indirect but strong. In LangChain’s survey (1,340 responses) 57.3% run agents in production and 10k+ enterprises write in “ongoing difficulty managing context at scale” (LangChain). Claude Code passed a $2.5B run rate in Feb 2026 (Simon Willison), and 93% of its permission prompts are approved (NeuralTrust). Approval UX is broken; “local reversible runs now, external sends get a dedicated button” is the L1/L2/L3 answer.

2. supermemory は「開いたクライアント・閉じたエンジン」で、構造化状態と権限を持たない

2. supermemory: open clients, closed engine, no structured state, no permissions

supermemory は消費者製品（Nova、Company Brain）を 2026-09-09 に閉じて「メモリエンジン一本」に絞り（公式ブログ）、API v5（2026-10-07）、hosted MCP（17 ツール）、7 つのコーディングエージェント・プラグイン、SMFS、自己ホスト用バイナリを出している。資金は $2.6M シード（エンジェルに Jeff Dean、Cloudflare CTO）、チーム約 9 名、GitHub 31.4k スターは 2024 年の消費者アプリから継承（GitHub）。

MIT リポジトリにメモリエンジンは入っていない。 apps/{web,docs,mcp} と packages/{tools,validation,memory-graph,…} はすべて api.supermemory.ai を呼ぶクライアント。自己ホスト用バイナリは「別の非公開コードベースから構築」と明記され、Issue #1299「supermemory-server のソースはどこか」は 2026-07 から開いたまま。ローカル版は BYO モデルで品質が劣り、テレメトリ既定 ON、データ損失や OOM の Issue（#1826、#1827、#1806）が並ぶ。真にローカルファーストでエンジンが開いている立ち位置は丸ごと空いている。

データモデルも質的に異なる。グラフはノードが document | memory の 2 種、エッジが updates | extends | derives の 3 種で、人物やプロジェクトのエンティティは無い。自ら「system of record ではない。SQL も join も主キー検索も無い」と規定する（docs）。権限は MCP アノテーションと名前空間ごとの read/write だけで、行動階層・確認フロー・エージェント書き込みの監査は無い。既定の dreaming では新しい名前空間は数分間メモリ 0。CJK テキストが索引されない Issue #1740 も開いており、日本語 132 問で R@5 0.985 を出す ShogunAI にとって直接の差別化点になる。

ベンチマークは「#1 on every major AI memory benchmark」を掲げるが、看板の 97% は Recall@20 で、同じレポートの end-to-end 正答率は 81.6〜85.2%（supermemory）。競合運営の同一ハーネス OmniMemEval では LoCoMo 73.53／LongMemEval 66.07 で MemOS や Letta の下にいる（OmniMemEval）。

借りるべき設計

  • 名前空間を URL に置く v5（/ns/{namespace}/document）、include{documents,related,forgotten} による展開
  • dryRun 必須の一括 forget、who_am_i/list_spaces の発見ツール、破壊的／追加的のアノテーション分離
  • <supermemory context="user-memories" readonly> という置換可能・エスケープ済みのシステムプロンプト注入ブロック
  • SKILL.md ＋ npx supermemory help --json ＋ docs MCP という「エージェントが自分で導入する」三点セット
  • 逆に避けること：12 か月で 3 世代の API を回し 11 本の移行ページを抱える churn。ShogunAgent は v1 の wire name を凍結し 12 か月の非推奨ポリシーを最初から宣言する

supermemory shut its consumer products (Nova, Company Brain) on 2026-09-09 to go “all in on the memory engine” (blog) and now ships API v5 (2026-10-07), a hosted MCP with 17 tools, 7 coding-agent plugins, SMFS, and a self-host binary. Funding is a $2.6M seed (angels include Jeff Dean and Cloudflare’s CTO), the team is about 9 people, and the 31.4k GitHub stars were inherited from the 2024 consumer app (GitHub).

The MIT repo does not contain the memory engine. apps/{web,docs,mcp} and packages/{tools,validation,memory-graph,…} are all clients of api.supermemory.ai. The self-host binary is “built from a separate, non-public codebase,” and issue #1299 (“where is the supermemory-server source?”) has been open since July 2026. The local build runs on BYO models with lower quality, telemetry on by default, and open data-loss and OOM issues (#1826, #1827, #1806). A truly local-first product with an open engine is an unoccupied position.

The data model differs in kind. The graph has two node types (document | memory) and three edge types (updates | extends | derives); there are no person or project entities. The docs say it is “not a system of record: no SQL, no joins, no primary-key lookups” (docs). Permissions are MCP annotations plus per-namespace read/write; there are no action tiers, confirmation flows, or audit of agent writes. With default dreaming, a new namespace has zero memories for minutes. Issue #1740, CJK text never indexed, is still open, a direct differentiator for ShogunAI, which scores R@5 0.985 on 132 Japanese queries.

The “#1 on every major AI memory benchmark” claim rests on Recall@20 = 97%; the same report’s end-to-end accuracy is 81.6–85.2% (supermemory). On the competitor-run same-harness OmniMemEval it scores LoCoMo 73.53 / LongMemEval 66.07, below MemOS and Letta (OmniMemEval).

Designs worth borrowing

  • Namespace in the URL (/ns/{namespace}/document) and include{documents,related,forgotten} expansion
  • Mandatory dryRun on bulk forget, who_am_i/list_spaces discovery tools, separate destructive vs. additive annotations
  • A replaceable, escaped system-prompt block: <supermemory context="user-memories" readonly>
  • The self-onboarding trio: SKILL.md + npx supermemory help --json + a docs MCP
  • And one thing to avoid: three API generations in 12 months with 11 migration pages. ShogunAgent freezes v1 wire names and declares a 12-month deprecation policy on day one

3. ShogunAI の「難しい部分」は 70% 持ち越せるが、macOS 層は 0%

3. 70% of ShogunAI’s hard parts carry over; the macOS layer carries 0%

コードベース（約 330,000 行の Rust、テスト 5,719、マイグレーション V1〜V91、テーブル 114）のうち、ShogunAgent に差別化をもたらす資産は 8 つある。

  1. provenance ＋ confidence ＋ 逐語 quote 検証付きの状態モデルと supersession。 state_provenance が空の INSERT はリポジトリ層が拒否し、shogun-fusion/src/confidence.rs が High ≥0.8／Medium 0.5〜0.8／Low <0.5 を強制、半減期減衰、state_disputes、loop_signals → consolidator（MIN_CONFIDENCE 0.84、quote 完全一致）の二段構え。研究が「削除が派生エントリに伝播しない」と指摘する欠落への実装済みの答えで、GDPR Art.17 のカスケード削除をそのまま売れる。
  2. L1/L2/L3 と ApprovalQueue。 shogun-agents（依存ゼロ）の SendAction は型で L3、ApprovalOrigin {Ui, Api, Mcp, Cli} が同一フロー、10 分タイムアウト。
  3. 低コスト抽出パイプライン。 セッション化（行 1,650 → セッション 30〜80）、prefilter、anchor 検証、毎時冪等サイクル、relay 側スキーマ強制。docs/unit-economics.md は LLM 原価を $67.94 → $9.08 → $2.08/人・月と見積もる。これがそのまま抽出 API の粗利になる。
  4. ゼロ保持ゲートウェイ。 traceability_log は本文カラム無し、shogun-redact は秘密情報 recall 1.000・FP 0、instruction_shaped ゲートは OWASP ASI06「Memory and Context Poisoning」の書き込み経路防御そのもの。
  5. 評価ハーネス 6 種（memory-bench、pii-bench、dedup-bench、extract-eval、fusion-eval、日英 golden search eval）。
  6. 日本語品質（NFKC、送り仮名折り畳み、漢字 bigram）。
  7. shogun-memory-import/v1（ChatGPT/Claude/Cursor からの移行導線）。
  8. Memory API 三面対称。 158 ツール中 85 が Read、core 20 本は約 3k トークン、Claude Code/Codex/Cursor へ起動時に read 接続を自動投入。

持ち越せないのは取得層全部（AX、OCR、音声、ノッチ）、Keychain 依存の秘密保管、Tauri デスクトップ 86k 行、そして単一テナント前提（SQLCipher ファイル 1 個＝1 ユーザー、REST は 127.0.0.1:7464 固定、承認 UI はデスクトップ）。

Of the codebase (about 330,000 lines of Rust, 5,719 tests, migrations V1–V91, 114 tables), eight assets differentiate ShogunAgent.

  1. A state model with provenance, confidence, verbatim-quote verification and supersession. The repository layer rejects any INSERT with empty state_provenance; shogun-fusion/src/confidence.rs enforces High ≥0.8 / Medium 0.5–0.8 / Low <0.5, half-life decay, state_disputes, and a two-stage loop_signals → consolidator (MIN_CONFIDENCE 0.84, exact quote match). This is an implemented answer to the research finding that deletions rarely propagate to derived entries, and GDPR Art. 17 cascade deletion can be sold as is.
  2. L1/L2/L3 and ApprovalQueue. In dependency-free shogun-agents, SendAction is L3 by type, ApprovalOrigin {Ui, Api, Mcp, Cli} share one flow, 10-minute timeout.
  3. A low-cost extraction pipeline. Sessionization (1,650 rows → 30–80 sessions), prefilter, anchor verification, hourly idempotent cycles, relay-side schema enforcement. docs/unit-economics.md estimates LLM cost at $67.94 → $9.08 → $2.08 per person per month. That is the extraction API’s gross margin.
  4. A zero-retention gateway. traceability_log has no body column; shogun-redact scores secret recall 1.000 with 0 false positives; the instruction_shaped gate is exactly the write-path defense OWASP ASI06 “Memory and Context Poisoning” recommends.
  5. Six eval harnesses (memory-bench, pii-bench, dedup-bench, extract-eval, fusion-eval, JA/EN golden search eval).
  6. Japanese text quality (NFKC, okurigana folding, kanji bigrams).
  7. shogun-memory-import/v1 (migration path from ChatGPT/Claude/Cursor).
  8. Three-way symmetric Memory API. 85 of 158 tools are read-only, the core 20 cost about 3k tokens, and read connections are auto-installed into Claude Code/Codex/Cursor on launch.

What does not carry over: the whole capture layer (AX, OCR, audio, notch), Keychain-bound secret storage, the 86k-line Tauri desktop, and the single-tenant assumption (one SQLCipher file = one user, REST fixed to 127.0.0.1:7464, approval UI on the desktop).

shogun-core/src/bin/shogun_api.rs と shogun_mcp.rs は既に「DB パスを指定して立つ単体メモリサーバー」であり、Linux CI は全クレートが通る。最短経路は、このバイナリをテナントごとの SQLCipher ファイルで多重化し、apps/api を認証・計量の前段に置くこと。

欠けているものは 9 項目：テナンシー（Cloudflare Agent Memory も supermemory も「1 ユーザー＝1 Durable Object＋SQLite」を選んでおり、「1 人＝1 ワールドモデル」と一致）、エージェント認証（apps/api/src/auth.ts の Ed25519 トークンを流用）、汎用取り込み API、意味検索（埋め込み再導入）、承認フローの遠隔化（Web/Slack/webhook）、SDK と Streamable HTTP MCP、名前空間・ACL・監査、従量課金（Stripe metered）、サーバー側スケジューラ。

shogun-core/src/bin/shogun_api.rs and shogun_mcp.rs are already standalone memory servers that start from a DB path, and every crate passes Linux CI. The shortest path is to multiplex that binary across per-tenant SQLCipher files and put apps/api in front for auth and metering.

Nine things are missing: tenancy (Cloudflare Agent Memory and supermemory both chose “one user = one Durable Object + SQLite,” matching “one person = one world model”), agent auth (reuse the Ed25519 tokens in apps/api/src/auth.ts), a generic ingest API, semantic search (re-enable embeddings), remote approvals (web/Slack/webhook), SDKs and Streamable HTTP MCP, namespaces/ACL/audit, metered billing (Stripe metered), and a server-side scheduler.

4. プロダクト／API／アーキテクチャ：三つのインターフェース形状と MCP 2026-07-28 に合わせる

4. Product, API, architecture: serve all three interface shapes and MCP 2026-07-28

2026 年 10 月にエージェントが実際に呼ぶメモリ・インターフェースは三形状に収斂している。

  • ファイル形状：Anthropic の memory_20250818（view/create/str_replace/insert/delete/rename を /memories 配下で）、Claude Code の MEMORY.md（先頭 200 行／25KB）、Letta の git バック MemFS（Anthropic）。
  • 動詞形状の MCP ツール：標準名は無く、Cloudflare は ingest/remember/recall/forget/list を選んだ。
  • 予算付き文脈注入：Honcho の contextTokens、Mastra Observational Memory の安定・追記のみ観測ログ（プロンプトキャッシュで 4〜10× のコスト削減、Mastra）。

ShogunAgent は三つ全部に応えるべきで、既存資産で安い：memory.get_context_pack はそのまま予算付き注入 API、entity_pages の wikilink 付きページは /memories/people/<name>.md、/memories/projects/<id>.md、/memories/open_loops.md、/memories/INDEX.md という仮想ファイルシステムに射影でき、memory_20250818 の view にゼロ統合で応答できる。動詞形状は core 20 本を v1 として凍結し、memory.ingest(events[] | turns[], source, actor, thread_key, metadata) と memory.recall(query, budget_tokens) を追加する。

MCP 2026-07-28 仕様への写像

この版は initialize と Mcp-Session-Id を廃してステートレス化し、Mcp-Method／Mcp-Name ヘッダを必須化、list/read 応答に ttlMs／cacheScope、サーバー起点 elicitation を Multi Round-Trip Requests（input_required）に置き換え、DCR を CIMD へ移した。Tier 1 SDK は月間約 5 億ダウンロード（MCP）。含意は三つ：

  1. Mcp-Method/Mcp-Name でプロキシ層計量が無料になり、per-operation 課金が apps/api の reserve-then-settle 台帳にそのまま載る。
  2. L1 = 即時、L2 = MRTR input_required のフォーム確認、L3 = URL モード elicitation で帯域外の人間承認という標準準拠の写像が得られ、ApprovalOrigin::Mcp の既存キューがそのまま裏側になる。
  3. ロードマップが agent identity（DPoP、WIF、ID-JAG）と progressive discovery を優先項目に置いた以上（MCP roadmap）、ACL はいまから tenant × agent × end-user の 3 軸で設計する。

組織境界を越える引き渡しには A2A v1.0 の署名付き Agent Card を出す。A2A は「メッセージ」を運ぶが引き渡し内容は無標準で、7 製品を試した検証は「メモリ可搬性は実質存在しない」と結論した（dev.to）。可搬性標準は W3C AI Agent Memory Interoperability CG（2026 年 6 月憲章）と 4 形式が競合中で、公開エクスポート形式を初日から出し CG に参加するのが正しい賭けである。

アーキテクチャの判断

業界は「生の証拠 → 型付き・双時間・provenance 付き状態 → 要約」の三層＋背景統合に収斂し、ShogunAI の event_log → state → period_summaries ＋ Dream Cycle を裏書きする。同時にグラフ「エンジン」は退潮：Mem0 は traversable な relations を外し、Graphiti は Kuzu を非推奨、Kuzu は Apple 買収で 2025-10 にアーカイブ（The Register）。SQLite の型付き関係行と再帰 CTE で十分で、グラフ DB は買わない。埋め込みは fastembed-rs ＋ Qwen3-Embedding-0.6B または nomic をローカル既定にし、ベンチマーク全腕で固定する（MemDelta は埋め込みの差し替えだけで +6.2pp 動き結論が反転することを示した）。

ベンチマークは LoCoMo を追わない：Penfield Labs の監査で解答キーの 6.4% が誤り、既定の LLM 採点者は意図的な誤答の 62.81% を受け入れた（Penfield Labs）。信頼を得る方法は OmniMemEval と Mem0 公開ハーネスでの同一ハーネス走行と、誰も測っていない「オープンループ／コミットメント追跡」ベンチを自分で定義すること。memory-bench の既知の弱点（temporal recall@1 0.000、abstention false-evidence 100%）は公開前に閉じる。

セキュリティは機能である。メモリ汚染（MINJA、OWASP ASI06）への推奨緩和策は sanitize::persist_body、state_provenance.quote、L2/L3 承認として実装済み。agent-scratch 名前空間を principal のワールドモデルから分離し、全書き込みに actor を記録する。ユーザー保持鍵による暗号化は商用メモリベンダーに存在せず（AWS は CMK のみ）、SQLCipher ＋ Keychain 鍵の既存設計は「鍵をユーザーが持つ」階層として売れる。

By October 2026 the memory interfaces agents actually call have converged on three shapes.

  • File-shaped: Anthropic’s memory_20250818 (view/create/str_replace/insert/delete/rename under /memories), Claude Code’s MEMORY.md (first 200 lines / 25KB), Letta’s git-backed MemFS (Anthropic).
  • Verb-shaped MCP tools: no standard names; Cloudflare chose ingest/remember/recall/forget/list.
  • Budgeted context injection: Honcho’s contextTokens, Mastra Observational Memory’s stable append-only log (4–10× cheaper via prompt caching, Mastra).

ShogunAgent should serve all three, cheaply, from existing assets: memory.get_context_pack is already a budgeted injection API; wikilinked entity_pages project onto a virtual filesystem (/memories/people/<name>.md, /memories/projects/<id>.md, /memories/open_loops.md, /memories/INDEX.md) that answers memory_20250818’s view with zero integration. For verbs, freeze the core 20 tools as v1 and add memory.ingest(events[] | turns[], source, actor, thread_key, metadata) and memory.recall(query, budget_tokens).

Mapping onto MCP 2026-07-28

This revision makes MCP stateless (no initialize, no Mcp-Session-Id), mandates Mcp-Method/Mcp-Name headers, adds ttlMs/cacheScope to list/read responses, replaces server-initiated elicitation with Multi Round-Trip Requests (input_required), and moves DCR to CIMD. Tier-1 SDKs see about 500M downloads a month (MCP). Three implications:

  1. Mcp-Method/Mcp-Name make proxy-layer metering free, so per-operation billing lands directly in apps/api’s reserve-then-settle ledger.
  2. A standards-compliant mapping: L1 = immediate, L2 = MRTR input_required form confirmation, L3 = URL-mode elicitation for out-of-band human approval, backed by the existing ApprovalOrigin::Mcp queue.
  3. With agent identity (DPoP, WIF, ID-JAG) and progressive discovery on the roadmap (MCP roadmap), design ACLs now on three axes: tenant × agent × end-user.

For cross-organization handoff, publish a signed A2A v1.0 Agent Card. A2A moves messages, but handoff content is unstandardized; a test of seven memory products found “no portability, all seven lock you in” (dev.to). Portability standards are contested between the W3C AI Agent Memory Interoperability CG (chartered June 2026) and four formats; the right bet is to ship a public export format on day one and join the CG.

Architecture calls

The industry has converged on three layers (raw evidence → typed, bi-temporal, provenance-carrying state → summaries) plus background consolidation, which endorses ShogunAI’s event_log → state → period_summaries + Dream Cycle. At the same time graph engines are receding: Mem0 removed traversable relations, Graphiti deprecated Kuzu, and Kuzu was archived in Oct 2025 after Apple acquired it (The Register). Typed relation rows in SQLite with recursive CTEs suffice; do not buy a graph DB. Default embeddings to fastembed-rs + Qwen3-Embedding-0.6B or nomic locally and pin them across every benchmark arm (MemDelta showed swapping embeddings alone moves accuracy +6.2pp and flips conclusions).

Do not chase LoCoMo: Penfield Labs found 6.4% of the answer key wrong and the default LLM judge accepting 62.81% of intentionally wrong answers (Penfield Labs). Earn trust with same-harness runs on OmniMemEval and Mem0’s public harness, and define the “open-loop / commitment tracking” benchmark nobody else measures. Close memory-bench’s known weaknesses (temporal recall@1 0.000, abstention false-evidence 100%) before publishing.

Security is a feature. The recommended mitigations for memory poisoning (MINJA, OWASP ASI06) are already implemented as sanitize::persist_body, state_provenance.quote, and L2/L3 approvals. Separate agent-scratch namespaces from the principal’s world model and record an actor on every write. No commercial memory vendor offers user-held-key encryption (AWS offers customer-managed keys only); the existing SQLCipher + Keychain design sells as a “you hold the key” tier.

5. 価格は $19 の階段に乗せ、計量は「取り込み」に置き、読み取りは無料にする

5. Pricing: ride the $19 ladder, meter ingest, make reads free

原則は三つ。第一に $19〜20 の開発者ティアは信用の前提（supermemory、Mem0、Letta、Pinecone、Browserbase が並ぶ）。実収益は $100〜400 と企業最低額（Pinecone $500/月、E2B $3,000/月）にある。第二にコンプライアンスが収益化レバー：SOC 2、HIPAA、BYOC、ZDR は全社が $399+ か Enterprise に閉じ、Composio は ZDR を +$0.0001/call のアドオンで売る。ローカルファーストの ShogunAgent は既定でデータが端末を出ないので、この姿勢を低ティアで提供し、同期・多端末・チーム共有・遠隔承認に課金できる。第三に COGS は抽出（LLM）が支配：GraphMem の試算で抽出 $2,000/百万文書 vs 埋め込み $130、MemDelta で Mem0 の書き込み経路はプレーン RAG の約 50×。原価のある場所（ingest）で取り、無い場所（lookup）で与える。

Three principles. First, a $19–20 developer tier is table stakes (supermemory, Mem0, Letta, Pinecone, Browserbase all sit there). Real revenue is in the $100–400 tiers and enterprise minimums (Pinecone $500/mo, E2B $3,000/mo). Second, compliance is the monetization lever: SOC 2, HIPAA, BYOC and ZDR are gated to $399+ or Enterprise everywhere; Composio sells ZDR as a +$0.0001/call add-on. Because ShogunAgent is local-first, data never leaves the device by default, so it can offer that posture low in the ladder and charge for sync, multi-device, team sharing and remote approvals instead. Third, COGS is dominated by LLM extraction: GraphMem estimates $2,000 per million documents for extraction vs. $130 for embeddings, and MemDelta puts Mem0’s write path at about 50× plain RAG. Charge where cost lives (ingest) and give where it doesn’t (lookup).

7. Monid 型アグリゲータは作らない。載る。ただし「日本向けの狭いカタログ」はゲート付きで残す

7. Don’t build a Monid-style aggregator. Get listed. Keep a gated “narrow Japan catalog” option

Monid（SF）は 2026-04 にローンチし、$2.1M プレシードと Long Journey Ventures 主導の $7.7M シードで合計 $9.8M を調達、api.monid.ai の discover／inspect（無料）／run（従量）と一つのプリペイド・ウォレット（または x402 の USDC）、MIT のコネクタ・エンジンを持つ「OpenRouter for agent tools」である（GitHub）。しかし中身はデータ取得ルーター：ランキング上位は TinyFish（754K 呼び出し）、TikHub、Context.dev、AnyAPI、Litescrape とすべて Web 検索／スクレイプ／ソーシャルデータで、記憶・知識・状態のカテゴリは存在しない（rankings）。独立レビューは、1 サプライヤー（TikHub）が端点の 56%、PER_CALL 価格の中央値 $0.0015、discover が 26 倍高い端点を 1 位に出し、/terms と /privacy が 404 と報告した（Notis）。「0% markup」と「10% 手数料」という収益モデルの矛盾も未解消。

自分で建てるべきでない五つの理由

  1. コードはコモディティ：コネクタ・エンジンは MIT で 780 フォーク。難しい部分（ウォレット、プロバイダ契約、ランキング・テレメトリ、法務、不正対策）は非公開で資本集約的。
  2. 薄利の規模ゲーム：OpenRouter は約 5% のテイクで年換算 $140〜160M に達し Stripe に $7B 超で買収されたが、それは約 $2.5B の中継支出の上に成り立つ（Sacra）。中央値 $0.0015/call で 10% を取っても、Monid の 400 万トランザクション全部が有料でも粗取りは数千ドル規模（推定）。RapidAPI は $1B 評価から資産売却に至った。
  3. 統合が進む：Arcade が Smithery を買収（2026-08-05）、Stripe が OpenRouter を買収。決済・認証の既存勢力がレジストリを吸収する局面で正面衝突する意味は薄い。
  4. 利益相反：自分が順位付けするカタログに自社製品を入れれば Monid が Simple FS で受けている批判をそのまま受け、OpenAI の提出規約は他プラグインへの誘導を禁じる。
  5. 記憶は per-call スポット市場に合わない：記憶はユーザー／テナントに束縛された状態で、継続とともに価値が複利で増え、乗り換えが価値を壊す。だから Monid に記憶が無く、記憶ベンダーは Composio/Smithery/Glama の中で自社サブスクで売っている。

答えは「(b) 載る」を核に、「(c) 両方」を再定義して残す。 載る先は優先順に、公式 MCP Registry、Anthropic directory、Smithery、Glama、Composio toolkit、OpenAI Plugin directory。L1/L2/L3 は MCP アノテーションに直接写像できる（Read → readOnlyHint:true、L1 → destructiveHint:false、L3 → destructiveHint:true かつ openWorldHint:true）ので、これは全ディレクトリの入場券である。Monid には、記憶カテゴリが追加された時点で per-call provider として掲載する。

(c) の再定義は「汎用ルーター」ではなく「日本 SaaS 向けの狭いコネクタ・カタログを、ShogunAgent の MCP/REST/CLI と SKILL.md 越しに、L1/L2/L3 を差別化として出す」である。日本の主要 SaaS 100 のうち公式 MCP は約 20%、「残り 65% は MCP サーバーが存在しない」、法務・電子契約（CloudSign、GMO Sign、LegalOn）は MCP ゼロという調査がある（Zenn）。shogun-integrations は 4 ファイルで新サービスを足せる設計で、scope.rs の「表に無い操作は拒否、ExternalSend は必ず L3」が、Monid にはワークスペース単位の予算しか無い穴を埋める。ただしこれは「ワールドモデルへの取り込みソース」として始め（freee/kintone/Sansan/Chatwork の読み取り）、課金付きカタログにするかは 12 か月目に判断する。アグリゲータが構造的に持たない「このユーザーでどのツールがどのタスクに効いたか」は per-user 状態であり、ShogunAgent はそれをユーザー所有の状態として持てる。

Monid (SF) launched in April 2026 and has raised $9.8M ($2.1M pre-seed, $7.7M seed led by Long Journey Ventures). It is “OpenRouter for agent tools”: api.monid.ai with discover/inspect (free) and run (metered), one prepaid wallet (or x402 USDC), and an MIT connector engine (GitHub). Inside, it is a data-fetch router: the top-ranked tools are TinyFish (754K calls), TikHub, Context.dev, AnyAPI and Litescrape, all web search/scrape/social data, and there is no memory, knowledge or state category (rankings). An independent review found one supplier (TikHub) behind 56% of endpoints, a median PER_CALL price of $0.0015, discover ranking a 26× more expensive endpoint first, and /terms and /privacy returning 404 (Notis). The “0% markup” vs. “10% fee” contradiction is unresolved.

Five reasons not to build one

  1. The code is a commodity: the connector engine is MIT with 780 forks. The hard parts (wallet, provider contracts, ranking telemetry, legal, fraud) are closed and capital-intensive.
  2. It is a thin-margin volume game: OpenRouter reached $140–160M annualized on a ~5% take and sold to Stripe for $7B+, on top of ~$2.5B routed spend (Sacra). At a $0.0015 median price, even a 10% take on all 4M of Monid’s claimed transactions is thousands of dollars (estimate). RapidAPI went from a $1B valuation to an asset sale.
  3. Consolidation is underway: Arcade acquired Smithery (2026-08-05), Stripe acquired OpenRouter. Payments and auth incumbents are absorbing registries; a head-on fight is low-value.
  4. Conflict of interest: listing your own product in a catalog you rank invites the criticism Monid gets for its Simple FS, and OpenAI’s submission rules forbid steering to other plugins.
  5. Memory does not fit a per-call spot market: it is user- and tenant-bound state whose value compounds with continuity and breaks on switching. That is why Monid has no memory and memory vendors sell their own subscriptions inside Composio/Smithery/Glama.

The answer is (b) get listed, with (c) redefined and kept. Listing targets in priority order: the official MCP Registry, the Anthropic directory, Smithery, Glama, a Composio toolkit, the OpenAI Plugin directory. L1/L2/L3 maps directly to MCP annotations (Read → readOnlyHint:true, L1 → destructiveHint:false, L3 → destructiveHint:true and openWorldHint:true), which is the entry ticket to every directory. List on Monid as a per-call provider once a memory category exists.

The redefined (c) is not a general router but a narrow connector catalog for Japanese SaaS, exposed through ShogunAgent’s MCP/REST/CLI and SKILL.md, with L1/L2/L3 as the differentiator. A survey of Japan’s top 100 SaaS finds about 20% with an official MCP, “65% with no MCP server at all,” and zero MCP in legal/e-signature (CloudSign, GMO Sign, LegalOn) (Zenn). shogun-integrations adds a service in four files, and scope.rs’s “deny anything not in the table, ExternalSend is always L3” fills the gap where Monid has only workspace-level budgets. Start it as an ingest source for the world model (reads from freee/kintone/Sansan/Chatwork) and decide at month 12 whether to monetize it as a catalog. What an aggregator structurally cannot own, “which tool worked for which task for this user,” is per-user state that ShogunAgent can hold on the user’s behalf.

8. 決定事項：何を建て、何を建てないか

8. Decisions: what to build, what not to build

ポジショニング。「AI エージェントが装着する、仕事の状態（state of work）レイヤー」。競合比較の軸は「記憶 vs 状態」「自由文 vs 型付きテーブル＋confidence」「クラウドファースト vs ローカル既定」「削除ツールを渡さない vs L1/L2/L3 を型で強制」「Recall@20 vs 同一ハーネス公開」。docs/gpt6-astra-implications.md の結論「Astra 級実行エンジンにワールドモデルと承認境界を貸す側に回る」と整合する。

Positioning. “The state-of-work layer AI agents plug into.” Comparison axes: memory vs. state, free text vs. typed tables with confidence, cloud-first vs. local by default, “don’t hand over the delete tool” vs. L1/L2/L3 enforced by type, Recall@20 vs. published same-harness results. This matches the conclusion of docs/gpt6-astra-implications.md: lend the world model and the approval boundary to Astra-class execution engines.

結論

Conclusion

この調査が変えた理解は二つある。第一に、「エージェント向けメモリ」はもう市場カテゴリではなく、四つの別製品（型付きビジネス知識、証明付き学習、セッション状態、ユーザー個人化）の総称であり、ラボが無料で出すのは最後の一つだけだという点。ShogunAI が 2 年かけて作った「provenance と confidence を一箇所で強制し、送信を型で L3 に閉じ込める」仕組みは、個人化記憶の世界では過剰設計に見えたが、仕事の状態を複数のエージェントに貸す世界では最低要件になる。第二に、Monid と OpenRouter の分析が示すのは、エージェント経済で「集める」側（ルーター、レジストリ、ウォレット）は決済・認証の既存勢力に吸収されつつあり、独立して残るのは「状態を持ち、継続で価値が増え、乗り換えが痛い」層だという点。ShogunAgent はまさにその層にいる。

実行上の含意は、ShogunAgent を「新製品」ではなく「shogun_api バイナリの多重化と Memory API のブランド化」として始め、最初の 90 日はコードより配布（SKILL.md、プラグイン、レジストリ、同一ハーネス公開）に重心を置くこと。残る問いは「日本の購買担当がこの準拠の形を評価するか」と「Mac を持たない開発者が取り込み API だけで十分な状態を得られるか」の二つで、どちらも design partner 5 社で 90 日以内に答えが出る。

This research changed two understandings. First, “agent memory” is no longer a market category but an umbrella over four products (typed business knowledge, verified learning, session state, user personalization), and the labs give away only the last. The machinery ShogunAI spent two years building, enforcing provenance and confidence in one place and locking sends into L3 by type, looked over-engineered for personalization memory, but becomes the minimum requirement when state of work is lent to many agents. Second, the Monid and OpenRouter analysis shows that the “aggregating” side of the agent economy (routers, registries, wallets) is being absorbed by payments and auth incumbents, and what stays independent is the layer that holds state, compounds with continuity, and hurts to leave. ShogunAgent sits exactly there.

The execution implication: start ShogunAgent not as a new product but as “multiplexing the shogun_api binary and branding the Memory API,” and spend the first 90 days on distribution (SKILL.md, plugins, registries, same-harness publication) more than code. Two questions remain: whether Japanese buyers value this form of compliance, and whether developers without a Mac get enough state from the ingest API alone. Five design partners answer both within 90 days.
