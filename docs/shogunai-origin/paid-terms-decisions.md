### カード必須化がこの文書を P0 に押し上げた理由

現行 Terms の課金条項はこう書いています:

> Prices, billing intervals, included features, renewal, cancellation, and refund terms are
> **shown before purchase**.

これは「購入画面で見せるから規約には書かない」という委譲です。**トライアル開始時にカードを取る決定
（#551）で、この委譲が成立しなくなりました。** カードを預かる時点が「購入前」なので、返金・解約・
自動更新の条件は**カードを求める画面より前に読める場所に無ければなりません**。

#### 電話番号を出さない場合に必要なこと

**オーナー判断: 公開しない。** 特商法（通信販売）の広告表示事項は、**「請求があった場合に遅滞なく提供する」
旨を表示し、実際に遅滞なく提供できる体制がある**ときに一部を省略できる扱いです（施行規則の省略規定）。
実務上、電話番号をこの形で省略している事業者は多くあります。**ただしこれは弁護士の確認が要る論点**で、
この文書は法律の助言ではありません。

そして重要な依存があります: **省略の根拠が「請求があれば遅滞なく提供する」である以上、その請求を
受け取れる窓口が実在していなければ成立しません。** 受信できるメールアドレスが無い状態
で電話番号も出さないと、消費者が事業者に到達する手段がゼロになります。
**2026-09-23 時点で MX は生きている**ことを確認済み（§2-2）なので前提は満たされていますが、
**`info@` の受信をテストメールで一度確認すること**が、電話番号を出さない判断の条件になります。

**Stripe は電話番号の削除を受け付けません**（2026-09-23 実測: 空欄で保存すると "Please provide a phone number."）。
ただし Stripe には**「レシート・請求書に表示する」かどうかの別設定**があり、**こちらは元から OFF** でした。

したがって最終状態は **「Stripe には登録されているが、顧客向けには表示しない」** で、
「電話番号は公開しない」という判断と両立しています。特商法ページにも記載しません。

**未確認が1点:** Checkout 画面での実表示。**確認できていません。**
このセッションからは headless Chromium で Checkout を開けず（社内プロキシの TLS 終端を
ブラウザが信頼せず、TLS 検証を切るのは禁止）、初期 HTML には社名も連絡先も含まれない
（すべてクライアント側描画）ため、**「出ていない」とは断定できません。**
Checkout のリンクを一度自分の目で開いて確かめてください。

#### 事前通知なしで成立させる条件

**オーナー判断は「トライアル終了の事前通知は出さず、購入時に開示する」。** そのまま実装すると2つに抵触します。

**(1) カードネットワークの要件（Stripe の公式ドキュメントに明記）**

> You must comply with card network requirements when you use trial offers.
> — [Manage compliance requirements for trials and promotions](https://docs.stripe.com/billing/subscriptions/trials/manage-trial-compliance)

同ページが求めているのは、トライアル終了リマインダー、領収書への解約方法の記載、解約導線、明細への表示です。
Visa の 2020 年のトライアル課金ルールが原型で、**守らない場合の costs は法令ではなくチャージバックと
アクワイアラからの指摘**という形で来ます。

**ただし、7日トライアルならオーナーの意図とほぼ衝突しません。** Stripe の既定は
**「終了7日前に送る。トライアルが7日未満なら開始と同時に送る」**。本件は7日なので、
**リマインダーはトライアル開始時に届きます** — つまり「購入時に開示する」という判断とほぼ同じタイミングです。
「終了直前に課金予告が来て解約を思い出させる」という、オーナーが避けたい形にはなりません。

→ **推奨: Stripe の trial-end reminder を有効化する。** 7日トライアルでは実質「開始時の確認メール」になります。
これで要件を満たしつつ、事前通知を独自実装しないで済みます。

なお明細表示について: トライアル終了後の課金には `* TRIAL OVER` が自動で付き、
descriptor は **10文字目以降が上書き**されます。現在の `SHOGUNAI` は8文字なので**そのままで問題ありません**。

**(2) 日本の特商法 — 「ちっちゃく入れる」が名指しで規制されている類型**

2022年施行の改正特商法は、継続課金（定期購入）について**申込みの最終確認画面**での表示義務を定めており、
分量・価格・支払時期・提供時期・解約の条件が対象です。**表示が小さい・分かりにくいことで誤認させた場合、
消費者に契約の取消権が発生**します（行政処分の対象でもあります）。

つまり「開示する」は正しく、**「ちっちゃく」は避けるべき**です。幸い Stripe Checkout は
「7日間無料、その後 $588/年」という形で目立つ位置に自動表示するため、**Checkout を使っている限り
この要件はほぼ自動的に満たせます**。自前の購入前画面を作るなら、そこでも同じ情報を同じ目立ち方で出すこと。

（本文書は法律の助言ではありません。特に上記(2)は弁護士の確認を推奨します。）

### 2-4. 税 — 【要決定】

§2-1 の MoR 判断に従属します。

| 対象 | 論点 | 備考 |
|---|---|---|
| 日本の消費税 | 課税事業者か / 価格は税込表示か税別か | 日本の消費者向けには**総額表示**が原則 |
| EU VAT | 登録するか、MoR 代行に委ねるか | `de` / `es` ロケールを公開している以上、EU 顧客は想定内 |
| 米国 sales tax | SaaS の課税は州ごとに異なる | nexus の有無で変わる |

**現状（2026-09-23 実測）:** Stripe Tax の**登録は 0 件**、価格は `tax_behavior: exclusive`（税別）、

自社が MoR である以上、これは「決めていない」ではなく「課税しない運用をしている」状態です。

### 2-5. 準拠法・管轄 — 【要決定】

| 項目 | 値 |
|---|---|
| 準拠法 | **日本法**（オーナー判断 2026-09-23） |
| 管轄裁判所 | **東京地方裁判所**（オーナー判断 2026-09-23）。本店はつくば市なので**合意管轄として明記が必要**（書かなければ水戸地裁土浦支部） |
| 消費者の強行法規 | 「本条は消費者に認められた強行法規上の権利を制限しない」旨を明記（**必須扱い。下記参照**） |

**日本法を選んでも、消費者には上書きされます。** 法の適用に関する通則法11条（消費者契約の特例）と、
EU の Rome I 規則6条は、いずれも**消費者の常居所地の強行規定が準拠法の選択に優先して適用される**と
定めています。EU 消費者については Brussels I bis により**自国の裁判所に訴える権利**もあり、
専属管轄条項は消費者相手には機能しません。

したがって条項の形は「日本法準拠・日本の裁判所を合意管轄とする。**ただし消費者が居住国の強行法規により
有する権利および裁判所へのアクセスを制限しない**」という併記が標準形です。この併記を落とすと、
条項そのものが不当条項として無効と判断されるリスクがあります。

### 3-1. 米国がメイン市場の場合に足りないもの（2026-09-23 追記）

**オーナー方針: グローバル販売、主戦場は米国。** この前提だと、上の §2-5 で決めた「日本法・東京地裁」は
**B2B には効きますが、米国の消費者相手には守りになりません**。米国向けで実際にコストになるのは次の順です。

> **注意:** この分野は動きが速く、本文書の記述は 2026年前半までの理解に基づきます。特に FTC の
> negative option rule（いわゆる click-to-cancel）は 2025年に連邦控訴審で無効とされた経緯があり、
> **現在の状態は必ず米国弁護士に確認してください。** ROSCA（連邦法）と州の自動更新法は生きています。

**(1) 自動更新法（ARL）と ROSCA — 米国 B2C サブスクの本丸**

カリフォルニア州の自動更新法が事実上の全米標準です。求められるのは:

| 要件 | 本件の現状 |
|---|---|
| 自動更新条件を購入前に明瞭に表示 | **Stripe Checkout が自動表示。OK** |
| 明示的な同意（チェックではなく購入行為で可） | Checkout で成立 |
| 購入後の確認メール（解約方法を含む） | **要設定。**サポート窓口が Stripe に未登録（§2-0）、決済メールはダッシュボード設定 |
| オンラインで簡単に解約できること | **Customer Portal。OK**（2026-09-23 に Terms / Privacy のリンクと戻り先 URL を設定済み） |
| **1年以上の契約は更新日の 15〜45日前に更新通知** | **未実装。該当する**（下記） |

**「事前通知なし」の決定と矛盾しません。** §2-3 で決めたのは「トライアル→本課金の前に通知を出さない」こと、
ここで要るのは「1年後の自動更新の前の通知」で、別の事象です。

**年払は実際に売れる構成です。** `src/lib/pricing.ts` は月払と年払の両方を持ち、**LP の見出し価格
（$49/mo, billed annually）は年払**です。`checkout/route.ts` の既定 interval も `annual`。
したがって 15〜45日前の更新通知は**該当します**。Stripe のダッシュボードで更新リマインダーを有効化し、
日数を 30 に設定してください（15〜45 の範囲内）。

**トライアルまわりは、コードを読むと想定より単純でした:**

- 【2026-10-23 オーナー再確認】カード登録必須、今日の請求額は $0、7日間 Pro。終了後の継続価格を提示し、事前にアプリ内から解約できる。アプリの `trial_only:true` 経路は7日を固定し、使用済みなら即時有料購入へ切り替えず拒否する。期間末解約後も残期間の利用権・領収書は維持する。カードは共有する別の生きた契約がなければ削除するが、削除失敗は解約成功と分けて正直に表示する。
- 【2026-10-20 更新】FR-BIL-06 の実装で、`TRIAL_REQUIRES_CARD`（既定 ON）のとき Checkout は **`trial_period_days: 7`** で開き、トライアルは Stripe 側に存在する（カード登録・終了時に自動で有料へ）。カードネットワークのトライアル規則（終了前のリマインダー等）は**この経路に掛かる**ので、Stripe のトライアル終了リマインダーメールを有効にすること。以下は 2026-10-20 以前の記述:
- `STRIPE_TRIAL_DAYS` の既定は **0**。つまり**通常購入では Stripe 側にトライアルが存在しません**
  （製品の7日間フルトライアルは Rust コアがローカルに持つもので、Stripe の課金とは別物）。
  **カードネットワークのトライアル規則は、この経路には掛かりません**
- Stripe から見た「無料」は **launch code の無料1ヶ月**（#580、`trial_end` で実装）です。
  こちらは約1ヶ月の無料期間なので**トライアル終了リマインダーが素直に該当**し、Stripe の既定
  （終了7日前）で要件を満たせます。**オンにしておくことを推奨します**

**(2) 仲裁条項とクラスアクション放棄 — venue より重要**

米国の消費者サブスクで現実に起きる紛争は、個別訴訟ではなく**自動更新法・ROSCA を根拠とする集団訴訟**です。
「東京地裁を専属管轄」と書いても米国の消費者集団訴訟を止める効果は期待できません。
米国向け標準形は**仲裁条項＋クラスアクション放棄**（AAA の消費者仲裁規則など）です。

**ただし mass arbitration（数千件の個別仲裁申立てで費用を積み上げる手法）という逆リスクもある**ため、
入れるかどうかは弁護士と決める論点です。**venue の決定（東京地裁）より優先度が高い判断**として記録します。

**(3) 州の sales tax — 当面は不要、ただし監視は今から**

米国の SaaS 課税は州ごとで、外国事業者にも economic nexus（多くの州で年 10万ドル または 200取引）が
適用されます。**単価が $588〜$1,188 なので、1州で10万ドルに達するのは相当先**です。それまで登録義務は
通常ありません。

- **SaaS が課税される州は約20**（ニューヨーク、テキサス、ワシントン、ペンシルベニア、マサチューセッツ など）
- **カリフォルニアは SaaS に課税しない** — 最大市場がここなのは有利
- → **推奨: 登録が無くても Stripe Tax を有効化する。** しきい値の監視機能があり、
  「いつどの州を越えたか」を自分で数えずに済みます。§2-4 の EU/UK 判断とも共通のインフラです

**(4) 米国の所得課税 — 恒久的施設が無ければ課税されない**

日米租税条約により、米国内に PE（恒久的施設）が無ければ事業所得は米国で課税されません。
また同条約の使用料条項は**税率0%**なので、仮に使用料と性質決定されても源泉徴収は生じない建付けです。

→ **実務上の準備物: `W-8BEN-E`。** 米国の法人顧客は支払前にこれを求めてくることがあります。
1枚用意しておけば足ります（B2C では通常求められません）。

**(5) CCPA/CPRA — 当面は閾値未満の可能性が高い**

カリフォルニア州プライバシー法の適用は「年間総収入 2,500万ドル超」「年間10万人以上の個人情報を取扱い」
「収入の50%以上が個人情報の販売」のいずれかです。**現時点ではいずれにも該当しない見込み**で、
PostHog の匿名プロダクト分析は「販売」に当たりません。**ただし該当し始める前に再確認すること。**

**(6) 米国向けの表示の置き場所**

日本の特商法表記ページはそのまま必要ですが、米国の ARL 要件は**購入導線上の表示**と**購入後メール**で
満たすものなので、ページを増やすより Checkout とレシートの設定で対応するのが筋です。
Terms には「Subscription terms（自動更新・解約・返金）」の節を独立させ、英語で読めるようにしておくこと。
