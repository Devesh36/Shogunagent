# Agent Infrastructure Stack and Protocol Layer: "Services Built for AI Agents as the Customer" (state as of October 2026)

Scope note: These notes map the "sell to agents, not humans" infrastructure stack and the protocol layer that shapes it, with concrete examples, pricing norms, funding, and a gap analysis aimed at positioning ShogunAgent (a memory / world-model / context service with L1/L2/L3 action-permission tiers, exposed via MCP/REST/CLI). Dates are given per fact. Reliability flags: [PRIMARY] = vendor/foundation/official page; [SECONDARY] = press or independent analysis; [VENDOR-BLOG] = competitor-authored or SEO comparison content, treat numbers as indicative; [SINGLE-SOURCE] = found in only one place.

Research was conducted 2026-10-25 with ~25 search/fetch calls. Where primary pages could not be fetched, the secondary source is named explicitly.

## Key Question 1: Stack map — sub-layers, leaders, pricing model, funding, and whether memory/context is bundled

### Takeaway
By October 2026 the agent-infra stack has crystallized into ~10 sub-layers, each with 2–3 funded leaders and converging pricing norms (free tier + usage metering per call/credit/trace, with $25–$250/month paid entry points and enterprise custom tiers). Memory/context is almost never bundled by tool, browser, sandbox, search, email, payments, or identity vendors; it is bundled only (a) inside orchestration frameworks (Mastra, OpenAI Agents SDK sessions, Anthropic's Managed Agents memory beta) and (b) by dedicated memory vendors (Mem0, Zep, Letta, Supermemory), which are cloud-first and small relative to adjacent layers.

### Inferences
- Pricing norm: every adjacent layer meters by atomic action (tool call, credit, trace, request, inbox) with a free tier and a $25–$250/month paid entry, then enterprise. A memory service that sells to agents will be expected to meter by read/write/recall operation and offer a free tier.
- Funding gravity is in search ($2B+ valuations for Exa and Parallel), payments (card networks + LF foundation), and identity (Okta/Microsoft/Google incumbents). Dedicated memory is comparatively under-capitalized (Mem0 ~$24M, Letta $10M), which signals either an under-exploited wedge or that platforms (Anthropic, OpenAI, Mastra) are expected to absorb memory.
- Across tool, browser, sandbox, search, email, payments, and identity layers, nobody holds "the state of the user's work" — each holds its own slice (credentials, cookies, traces, wallet). This is the structural opening for a world-model/context service, provided it interoperates with those layers rather than replacing them.

## Key Question 2: Protocols — MCP, A2A, AG-UI, ACP, memory/context portability standards, OpenAI Apps SDK, Anthropic skills/plugins; which should a memory service speak natively?

### Takeaway
MCP (2026-07-28 spec: stateless, HTTP-native, extensions model, OAuth hardening, agent-identity work underway) is the de facto agent-to-tool protocol with ~0.5B SDK downloads/month; A2A 1.0 (150+ orgs, Linux Foundation) is the agent-to-agent protocol; ACP (Zed) owns the editor-to-coding-agent seam and AG-UI the agent-to-frontend seam. No memory/context portability standard has been adopted — only a June 2026 W3C Community Group charter, an IETF side meeting, and at least four competing community formats — so a memory service must speak MCP natively today, expose an A2A Agent Card for cross-org handoff, and treat portability formats as an open bet.

### Cited Findings

#### MCP (Model Context Protocol)
- The 2026-07-28 spec retires the `initialize`/`initialized` handshake and the `Mcp-Session-Id` header; each request carries protocol version, client identity, and capabilities in `_meta`; a new optional `server/discover` call fetches capabilities up front; any request can land on any instance behind a load balancer, with state passed explicitly (e.g., a handle minted by a tool). [PRIMARY] — [MCP blog: The 2026-07-28 Specification](https://blog.modelcontextprotocol.io/posts/2026-07-28/)
- Streamable HTTP requests must include `Mcp-Method` and `Mcp-Name` headers "so gateways can route and meter without parsing bodies"; list/read responses carry `ttlMs` and `cacheScope` hints. [PRIMARY] — [MCP blog 2026-07-28](https://blog.modelcontextprotocol.io/posts/2026-07-28/)
- Sampling, Roots, and Logging are deprecated (kept at least 12 months). Elicitation is not deprecated; server-initiated elicitation is replaced by Multi Round-Trip Requests (MRTR, SEP-2322): server returns `resultType: "input_required"` and the client retries with `inputResponses`. [PRIMARY] — [MCP blog 2026-07-28](https://blog.modelcontextprotocol.io/posts/2026-07-28/); contradicted in part by [mcpservers.org commentary](https://blog.mcpservers.org/posts/mcp-spec-2026-07-28) which says elicitation was deprecated — the official blog and [elicitation spec page](https://modelcontextprotocol.io/specification/2026-07-28/client/elicitation) still document elicitation (form and URL modes).
- Authorization: authorization servers should return RFC 9207 `iss`; clients set `application_type` during DCR so localhost redirects are accepted; credentials bound to issuer; **Dynamic Client Registration is formally deprecated in favor of Client ID Metadata Documents (CIMD)**. [PRIMARY] — [MCP blog 2026-07-28](https://blog.modelcontextprotocol.io/posts/2026-07-28/)
- Tasks moved from experimental core into the `io.modelcontextprotocol/tasks` extension (SEP-2663) with poll-based `tasks/get`, new `tasks/update`, and a single `subscriptions/listen` notification stream. Formal extensions framework includes Tasks, MCP Apps (inline interactive UI), Skills over MCP, and Enterprise Managed Authorization (EMA). Formal 12-month deprecation policy; legacy HTTP+SSE transport deprecated. [PRIMARY] — [MCP blog 2026-07-28](https://blog.modelcontextprotocol.io/posts/2026-07-28/); [AAIF: MCP 2026 changes](https://aaif.io/blog/mcp-2026-changes-the-rules); [channel.tel summary](https://www.channel.tel/blog/mcp-2026-spec-extensions-tasks-authorization)
- Adoption: "Tier 1 SDKs see close to half a billion downloads a month"; TypeScript and Python SDKs have each passed 1 billion total downloads; Honeycomb reports "nearly 20% of all monthly interactive queries are now made by agents." [PRIMARY] — [MCP blog 2026-07-28](https://blog.modelcontextprotocol.io/posts/2026-07-28/)
- Roadmap (published Aug 22, 2026) has five priorities: (1) agentic messaging primitives — longer-running loops, server-pushed streamed results, mid-flight steering, server-initiated events (webhooks/channels), moving Tasks into spec; (2) HTTP-native transport unification, extending Streamable HTTP to local servers that use stdio; (3) **agent identity and enterprise security** — standardize how servers recognize agent identities, building on DPoP, Workload Identity Federation, ID-JAG, token exchange, with IETF OAuth and WIMSE working groups; (4) improved primitives — standardized tool result handling and **progressive discovery** of tool catalogs; (5) SDK DX. The Server Card Working Group is defining `.well-known` metadata so a server can be discovered and assessed without connecting. [PRIMARY] — [MCP blog: The New MCP Roadmap](https://blog.modelcontextprotocol.io/posts/mcp-roadmap/)
- Version history reference: — [MCP specification version timeline](https://hidekazu-konishi.com/entry/mcp_specification_version_timeline.html); breaking changes with fixes: [Stacktree](https://stacktr.ee/blog/mcp-2026-spec-changes)

## Key Question 5: Gap analysis — where are "shared state of work across agents + humans," "agent-to-agent context handoff," "permission/approval tiers for agent actions," and "local-first / zero-retention agent memory" underserved?

### Takeaway
All four are underserved relative to adjacent layers: shared work-state across agents and humans has no dominant product (only patterns and hackathon projects); agent-to-agent handoff is addressed at the messaging layer by A2A but not at the context/memory layer, where portability "does not exist"; permission tiers exist as vendor blog patterns and IdP policies but no standard taxonomy, while MCP's elicitation/MRTR offers the hook; local-first/zero-retention memory is served mainly by open-source hobby projects (MemPalace, SuperLocalMemory, Mimir) rather than funded companies, as the funded memory vendors went cloud-first.

### Cited Findings

#### Shared state of work across many agents + humans
- A context-engineering survey describes common cross-agent context sharing patterns: embedding previous context into prompts (often reformatted) and exchanging structured messages with fixed schemas; it names Letta and MemOS as structured-approach systems. — [arXiv 2510.26493: Context Engineering 2.0](https://arxiv.org/pdf/2510.26493)
- Enterprise framing: "shared context repositories give each agent a role-specific slice of the same certified truth"; MCP and A2A handle tools and coordination "while the context layer keeps business meaning consistent." [VENDOR-BLOG] — [Atlan: context engineering for multi-agent systems](https://atlan.com/know/context-engineering/context-engineering-for-multi-agents/)
- Lyzr (Aug 2026) frames the challenge as "keeping information accurate as work moves between agents, and being able to show it stayed governed." [VENDOR-BLOG] — [Lyzr: context engineering](https://lyzr.ai/blog/context-engineering/)
- Coding-agent practice: a shared `.ai/` handoff directory so the next agent "does not re-discover architecture or repeat finished work." — [skillselion agent-handoff skill](https://skillselion.com/skills/wecansync/agent-skills/agent-handoff)
- The LangChain survey reports neither memory nor multi-agent findings, and 10k+ enterprises cite "managing context at scale." [PRIMARY] — [LangChain](https://langchain.com/state-of-agent-engineering)
- No source found describing a shipped product whose primary job is "the current state of a human's work (people, projects, commitments, open loops) shared across multiple agents." (See Gaps.)

#### Agent-to-agent context handoff
- A2A v1.0 provides signed Agent Cards and cross-org messaging but the LF release describes it as governing "how agents communicate," not how memory/context is transferred. [PRIMARY] — [Linux Foundation](https://linuxfoundation.org/press/a2a-protocol-surpasses-150-organizations-lands-in-major-cloud-platforms-and-sees-enterprise-production-use-in-first-year)
- ContextChain (hackathon project) proposes a typed "Episodic Memory Object" per agent carrying decisions, reasoning trace, and provenance, arguing "handoffs via raw dumps are expensive and noisy, or via compressed summaries are lossy because they drop the reasoning," and that "by the third or fourth handoff agents reason over degraded context." — [lablab.ai: ContextChain](https://lablab.ai/submissions/y3yi9ptyt665avp17d638f2p)
- Handoff tension: passing the full conversation may expose irrelevant or sensitive information; passing too little omits constraints. — [Promptmetheus: Agent Handoff](https://promptmetheus.com/resources/llm-knowledge-base/agent-handoff)
- Portability of memory across products "does not exist" (7 products tested, July 2026); W3C CG chartered June 2026; competing formats MIF, memorywire, OMP, OAMP, Engram. — [dev.to 7-product test](https://dev.to/stantyan/i-tested-7-ai-memory-products-for-portability-all-7-lock-you-in-31pm); [W3C CG](https://www.w3.org/community/ai-agent-memory-interop/); [HackerNoon](https://hackernoon.com/agent-memory-has-a-lock-in-problem-open-formats-are-how-we-fix-it)
- MCP roadmap explicitly adds "agentic messaging primitives" (server-pushed results, mid-flight steering) — messaging, not shared memory. [PRIMARY] — [MCP roadmap](https://blog.modelcontextprotocol.io/posts/mcp-roadmap/)

#### Permission / approval tiers for agent actions
- HITL is described as pausing execution at checkpoints for a human to approve/reject/modify; vendors tier actions by risk (irreversible actions such as bulk email, dropping a table, financial trades in the strictest tier); trusted agents on low-risk actions proceed automatically; "certain Tier 3 actions can be downgraded to Tier 2 for trusted agents operating within specific parameters." ### Inferences
- **Shared work-state is the widest gap.** Every layer stores its own slice; orchestration frameworks store per-app sessions; memory vendors store per-user facts. Nobody in the mapped stack claims "the inferred state of a person's work shared by all their agents and humans." That is ShogunAI's existing capability and the most defensible wedge for ShogunAgent, provided it is exposed via MCP (reads) and A2A (handoff).
- **Handoff is a context problem A2A does not solve.** A2A moves messages; the content of a handoff (decisions, open loops, commitments, provenance) is unstandardized. A memory service that emits a typed, provenance-carrying "state of work" object on A2A handoff would fill a hole both the LF A2A release and ContextChain identify.
- **Permission tiers are a product feature today, a protocol feature tomorrow.** MCP's MRTR/elicitation URL mode and the agent-identity roadmap give a standards path; the 93% approval rate shows the UX need. ShogunAgent's L1/L2/L3 maps cleanly onto "auto / form-mode confirm / out-of-band URL approval," and tier downgrade policies ("trusted agents within parameters") are an explicitly requested capability in vendor literature.
- **Local-first/ZDR is served by hobby OSS, not companies.** This leaves room for a commercially supported local-first memory with an optional ZDR sync tier — especially since security is the #2 enterprise blocker and the funded competitors are cloud-first.
- Risk: platform-native memory (Anthropic Managed Agents memory beta, OpenAI sessions, Mastra) may absorb single-app memory; the defensible layer is cross-agent, cross-vendor, human-inclusive state, which platforms are structurally disinclined to build neutrally.
