# AI-Agent Memory & World-Model Systems: Technical State of the Art (as of October 2026)

Research scope: benchmarks, architectures, 2025–2026 papers, privacy/security, implementation stack, and agent-facing interfaces, to inform ShogunAgent (memory / world-model / context service spun out of ShogunAI). All dates are the source's publication or last-checked date; "vendor claim" means self-reported by the system's maker, "same-harness" means a third party ran several systems under one configuration. Where two sources conflict, both are given. This file merges two research passes (an earlier draft and a second pass on 2026-10-25); duplicate findings were consolidated.

## Key Question 1: Benchmarks — which are credible, what do leaders claim?

### Takeaway
There is no official or neutral leaderboard for any major agent-memory benchmark; the 90–95% headline numbers on LoCoMo/LongMemEval are vendor self-reports that collapse by 15–40 points when a third party runs the same systems under one harness (OmniMemEval), independent audits show LoCoMo's answer key is ~6.4% wrong and its default LLM judge accepts ~63% of deliberately wrong answers, and a controlled study (MemDelta, Jun 2026) shows the embedding model and reader-model family alone can flip "memory beats RAG/full-context" conclusions. The benchmarks that still discriminate are BEAM (100K–10M tokens), MemoryAgentBench (ICLR 2026) and the new interactive/on-policy suites (AMemGym, MemoryBench). For ShogunAgent, "proving it" means publishing a same-harness run with named reader/judge models, ≥10 seeds, token budgets and latency, plus a workload-specific benchmark, not a single accuracy number.

### Cited Findings

**Benchmark definitions and known weaknesses**
- LongMemEval (Wu et al., ICLR 2025; arXiv Oct 2024): five abilities — information extraction, multi-session reasoning, temporal reasoning, knowledge updates, abstention; 500 curated questions; LongMemEval_S ≈115K tokens / ~40 sessions per history, LongMemEval_M ≈500 sessions; reports a ~30% accuracy drop for commercial assistants and long-context LLMs — [arXiv 2410.10813](https://arxiv.org/abs/2410.10813v2); [ICLR 2025 poster](https://iclr.cc/virtual/2025/poster/28290)
- LoCoMo: 10 dialogues, 1,986 QA pairs (1,540 non-adversarial used by most evaluators); four scored categories (single-hop, multi-hop, open-domain, temporal); LongMemEval: 500 questions in six categories; BEAM: 1M and 10M token scales across ten categories; DolphinBench: 600 tasks with real tool calls measuring task completion, cost and latency — [Mem0, "State of AI Agent Memory 2026"](https://mem0.ai/blog/state-of-ai-agent-memory-2026); [Benchmark Theatre essay, May 20 2026](https://essays.bloo-mind.ai/posts/2026-05-20-mem-eval/)
- Penfield Labs LoCoMo audit (Apr 4 2026): 99 score-corrupting errors in 1,540 questions (6.4%) → theoretical ceiling ≈93.6% for a perfect system; 24 speaker-attribution errors; hallucinated facts in the answer key (e.g., "Ferrari 488 GTB" only in an annotator field no memory system ingests); the standard gpt-4o-mini judge accepted 62.81% of intentionally wrong but topically adjacent answers; LoCoMo-Plus inherits all 1,540 original questions including the 99 errors — [DEV Community / Penfield Labs](https://dev.to/penfieldlabs/we-audited-locomo-64-of-the-answer-key-is-wrong-and-the-judge-accepts-up-to-63-of-intentionally-33lg)
- Benchmark Theatre essay (May 20 2026) consolidates: EverMemOS's reported 95.96% single-hop is above the 93.6% ceiling and "therefore impossible"; Wilson intervals show 56% of adjacent-pair comparisons on LoCoMo are statistically indistinguishable, and Open-Domain (n=96) needs a ~15-point gap; most vendors report single runs (Mem0 is the exception with 10 seeds); LoCoMo-Refined (Qwen3-14B judge) reached 86.33% human agreement vs 43.67% for the original setup; LongMemEval-S (~115K tokens) and LoCoMo (16–26K tokens) "test context management more than long-term memory" — [Benchmark Theatre](https://essays.bloo-mind.ai/posts/2026-05-20-mem-eval/)
- Zep's critique of LoCoMo (May 6 2025): conversations ~16,000–26,000 tokens; full-context GPT-4o-mini baseline (~73%) beat Mem0's best (~68%); no knowledge-update questions; category 5 (adversarial) unusable, so both Mem0 and Zep excluded it; speaker-attribution errors and ambiguous questions — [Zep blog](https://www.getzep.com/blog/lies-damn-lies-statistics-is-mem0-really-sota-in-agent-memory/)
- Mem0 itself concedes "smaller benchmarks like LoCoMo and LongMemEval can be materially improved by aggressive retrieval strategies, larger context windows, or frontier models" and lists variance sources: dataset revision, ingestion method, answer model, top-k, reranking, prompt format, judge leniency, recall-only vs end-to-end grading; "recall-only scores are systematically higher than end-to-end scores" — [Mem0 docs](https://docs.mem0.ai/core-concepts/memory-evaluation); [Mem0 State of Memory 2026](https://mem0.ai/blog/state-of-ai-agent-memory-2026)
- MemDelta (Kuan Wang, arXiv Jun 29 2026) — controlled protocol on LongMemEval-S varying one component at a time: verbatim RAG 47.2% vs full-context GPT-4o-mini 49.8% (p=0.34); Gemini gained +14pp from full context while Claude Sonnet gained +31pp from RAG because Sonnet refused 63% of full-context queries; swapping only the embedding model moved accuracy +6.2pp (p=0.004) and alone flipped the Mem0-vs-cloud-RAG conclusion; "agent self-memory" scored 42%, below basic retrieval at 47%; where Mem0 matched cloud RAG (72.7 vs 73.9, 2 of 6 question types) it cost ~50× more on the write path; recommends fixing embeddings, stratifying by model family and reporting write-path cost — [arXiv 2606.29914](https://arxiv.org/abs/2606.29914)
- BEAM ("Beyond a Million Tokens", Tavakoli et al., Univ. of Alberta / UMass Amherst, ICLR 2026, arXiv Oct 2025): 100 conversations (100K–10M tokens), 2,000 validated questions over 10 abilities; "even LLMs with 1M-token context windows, with or without retrieval augmentation, struggle as dialogues get longer"; LIGHT framework (episodic LTM + working memory + scratchpad) gains 3.5%–12.69% over strongest baselines; secondary summaries quote +155.7% (Llama-4-Maverick) at 10M, unverified against the PDF — [arXiv 2510.27246](https://arxiv.org/abs/2510.27246); [ICLR 2026 poster](https://iclr.cc/virtual/2026/poster/10006595); [DAIR.AI summary](https://academy.dair.ai/papers/beam-and-light)
- MemoryAgentBench (UCSD; arXiv 2507.05257, v4 Jun 28 2026; ICLR 2026): four competencies — accurate retrieval, test-time learning, long-range understanding, selective forgetting; converts long-context datasets into incremental multi-turn format; "current methods fall short of mastering all four competencies"; abstract names no systems — [arXiv 2507.05257](https://arxiv.org/abs/2507.05257)
- MemBench (arXiv Jun 2025): factual vs reflective memory; participation vs observation scenarios; effectiveness, efficiency, capacity — [arXiv 2506.21605](https://arxiv.org/html/2506.21605v1)
- AMemGym (HKUST + Meituan, ICLR 2026): interactive on-policy evaluation with LLM-simulated users; off-policy vs on-policy rankings differ by up to three positions; best on-policy 0.291 vs 0.253 off-policy; Claude Sonnet 4 peaked at 0.336 — [ICLR 2026](https://proceedings.iclr.cc/paper_files/paper/2026/hash/0856bc553d3e3b9827e5140d0ad3bf8d-Abstract-Conference.html); [Benchmark Theatre](https://essays.bloo-mind.ai/posts/2026-05-20-mem-eval/)
- MemoryBench (attributed to Tsinghua in the essay; 20,000 cases, 11 datasets): "none of the advanced memory-based LLMsys can consistently outperform RAG baselines"; Mem0 could not finish two task types; MemoryOS took >17 s per case for memory construction — [Benchmark Theatre](https://essays.bloo-mind.ai/posts/2026-05-20-mem-eval/) (I could not locate the MemoryBench paper directly; treat as secondary)
- MEMTRACK (Patronus AI): GPT-5 reaches 60% correctness; CASCADE: 20.9% macro-averaged improvement over zero-shot across 16 tasks — [Benchmark Theatre](https://essays.bloo-mind.ai/posts/2026-05-20-mem-eval/)
- LifeBench (Mar 2026, long-horizon multi-source memory): MemOS 55.22% overall, Hindsight second at 40.99%; authors say ~90% scores on LoCoMo/LongMemEval show those benchmarks "are becoming insufficient" — [arXiv 2603.03781](https://arxiv.org/pdf/2603.03781)
- Newer 2026 benchmarks: StreamMemBench (streaming, future-oriented assistance) — [arXiv 2606.14571](https://arxiv.org/pdf/2606.14571); DreamBench-SWE (multi-session memory hygiene for software agents) — [arXiv 2608.20664](https://arxiv.org/pdf/2608.20664); VibeMemBench (memory for coding agents on real repos) — [arXiv 2609.23570](https://arxiv.org/pdf/2609.23570); AgentMemBench (Aug 2026, five-family taxonomy, measures efficiency) — [arXiv 2608.00009](https://arxiv.org/pdf/2608.00009); LongMemEval-V2 (released 2026-05-12) is a separate web-agent memory benchmark where AgentRunbook-C leads at 72.5% — [benchmarklist.com](https://benchmarklist.com/benchmarks/longmemeval_v2/)

### Inferences
- A credible ShogunAgent proof is a published same-harness run (submit to OmniMemEval and run Mem0's open harness) reporting accuracy, context tokens per answer, write-path cost and p95 latency together, with reader and judge named, ≥10 seeds and confidence intervals, and a fixed embedding model across arms (MemDelta). Any single accuracy number will be dismissed given the Mem0/Zep/MemPalace history.
- Token-efficiency is a first-class axis: MemOS reaches 88.8 LoCoMo with 5.4K tokens while Hindsight needs 24.7K for 82.0; Zep uses 1.9K. ShogunAI's derived-state tier naturally yields compact context, a defensible benchmark story that also lowers per-query cost.
- LoCoMo and LongMemEval-S are near saturation for retrieval (95–97% recall) and bounded above by answer-key noise (~93.6% ceiling on LoCoMo). The differentiating categories are multi-session reasoning (~87% ceiling), knowledge updates / temporal reasoning, BEAM-10M (best ~56–65), MemoryAgentBench's test-time learning and selective forgetting, and on-policy interactive suites (AMemGym) — exactly where a world-model/state-table approach with validity intervals should show gains.
- None of these benchmarks measures ShogunAI's actual workload (screen text, meetings, email, calendar → people/projects/commitments/open loops). A ShogunAgent-specific benchmark ("open-loop / commitment tracking from heterogeneous event streams", in LifeBench/StreamMemBench style with on-policy simulated users) is needed, ideally paired with DolphinBench-style task-outcome metrics.

### Gaps
- No independent (non-vendor-owned) leaderboard exists; both OmniMemEval and agentmemorybenchmark.ai are run by competitors.
- The judge model for Mem0's 94.4/92.5 claims is not named; GPT-5.4 as Zep's reader/judge appears only on an aggregator.
- I could not retrieve the MemoryBench (Tsinghua) paper directly; its findings are quoted via a secondary essay. No reliable source found for STATE-Bench beyond Mem0's table.
- No per-system raw 1M–10M context baselines for GPT-5 / Claude / Gemini on BEAM beyond the paper's qualitative statement; no LongMemEval-M scores for top systems.
- No same-harness latency or $/query comparison across systems exists; only tokens per answer.

## Key Question 2: Architectures — what wins and at what cost?

### Takeaway
No single architecture wins across benchmarks: temporal-graph (Zep/Graphiti) wins on LoCoMo token efficiency but spends 117K tokens/answer on LongMemEval under the same harness; hierarchical/OS-style (MemOS, Mastra OM) leads same-harness accuracy with small contexts; "reasoning-substrate" designs (Hindsight, Agent Zero Memory) lead vendor claims but spend 4–5× more tokens; vector-only Mem0 has moved to hybrid (semantic + BM25 + entity) retrieval with an entity table replacing an external graph. Both frontier labs now ship the same shape as ShogunAI — OpenAI's ChatGPT loads a continuously rewritten user summary (no vector search at query time) produced by a background "Dreaming" process (Jun 2026), Anthropic's Managed Agents "dreaming" consolidates memory between sessions (May 2026), and Cloudflare's Agent Memory uses one SQLite-backed Durable Object per profile with supersession chains (Apr 2026). The field has converged on raw evidence → typed, bi-temporal, provenance-carrying state → compact summaries, with background consolidation and a stable, prompt-cacheable context prefix.

### Cited Findings

**Vector-only / hybrid retrieval (Mem0)**
- Mem0 April 2026: single-pass extraction; three parallel scoring passes (semantic, BM25 keyword, entity) fused; entity linking in a parallel `{collection}_entities` collection replaces external graph stores; the queryable `relations` field was removed, so relationships cannot be traversed (a regression for graph users); stores agent-generated facts alongside user facts; five memory types (working, episodic, semantic, procedural, hierarchical) with procedural "least mature"; scoping by `user_id`, `agent_id`, `run_id`/`session_id`, `app_id`/`org_id`; 20 vector-store backends, 21 framework integrations, 62,590 GitHub stars — [Mem0 State of Memory 2026](https://mem0.ai/blog/state-of-ai-agent-memory-2026)
- Under MemDelta's controls Mem0 beat MiniLM-RAG by +11pp but trailed a cloud-embedding RAG by 1.2pp, at ~50× the write cost on the subset where it matched — [arXiv 2606.29914](https://arxiv.org/abs/2606.29914)

**Temporal knowledge graph (Zep / Graphiti)**
- Graphiti (Apache-2.0 Python): bi-temporal model — facts carry validity windows (when true, when superseded); contradicted facts are invalidated (`invalid_at`) not deleted; queries can target "now" or any point in time; hybrid retrieval = semantic embeddings + BM25 + graph traversal "without relying on LLM summarization"; layers: episodic, semantic (entities/facts), community subgraphs; vendor paper (Jan 2025) claims 94.8% vs 93.4% (MemGPT) on DMR and "up to 18.5%" LongMemEval improvement with 90% latency reduction vs baseline — [Graphiti README](https://cdn.jsdelivr.net/gh/getzep/graphiti@main/README.md); [arXiv 2501.13956](https://arxiv.org/html/2501.13956v1)
- Backends (README, Oct 2026): Neo4j 5.26, FalkorDB 1.1.2, Amazon Neptune (+ OpenSearch Serverless for FTS), FalkorDBLite (embedded, Python 3.12+), Kuzu 0.11.2 **marked deprecated with a `DeprecationWarning`**; LLMs: OpenAI default, Anthropic/Gemini/Groq/Azure, OpenAI-compatible local servers (Ollama, vLLM, llama.cpp, LM Studio); "results most reliable with providers supporting structured output"; reference MCP server "not a production deployment, no authentication or prompt-injection protection" — [Graphiti README](https://cdn.jsdelivr.net/gh/getzep/graphiti@main/README.md)
- Zep deprecated its self-hosted Community Edition in April 2025; self-hosting now means running Graphiti plus your own graph DB; ingestion costs LLM calls per episode; Mem0's paper claimed Graphiti's footprint can reach 600,000+ tokens per conversation vs Mem0's 1,764 — disputed by Zep — [renezander guide](https://renezander.com/guides/graphiti-vs-mem0/); [mnemoverse Sep 2026](https://mnemoverse.com/docs/library/ai-memory-solutions-2026-q3)
- Same-harness: Zep/Graphiti uses 1,862 tokens on LoCoMo (lowest) scoring 63.83, but 117,106 tokens on LongMemEval scoring 79.80 — [OmniMemEval](https://github.com/MemTensor/OmniMemEval/blob/main/docs/user_memory/results.md)

**Hierarchical / OS-style (MemGPT→Letta, MemoryOS, MemOS, Mastra OM, EverMemOS)**
- Letta sleep-time compute (Apr 2025): primary agent (cannot edit core memory) + sleep-time agent (holds editing tools, rewrites in-context memory asynchronously); "raw context → learned context"; sleep agent can use a stronger model; memory blocks are labeled, character-limited context sections shareable between agents — [Letta blog](https://www.letta.com/blog/sleep-time-compute); [Letta docs](https://docs.letta.com/guides/agents/sleep-time-agents)
- Letta Context Repositories (Feb 12 2026): memory rebuilt as a git-backed local filesystem ("MemFS") — "every change to memory is automatically versioned with informative commit messages"; multiple subagents edit memory concurrently in isolated worktrees and merge via git conflict resolution; agents use bash/scripts over files instead of MemGPT-style database tools; progressive disclosure via folder/file names and frontmatter; `/init` imports from Claude Code / Codex histories; "defragmentation" skill; no benchmark evidence given — [Letta blog](https://www.letta.com/blog/context-repositories); Apr 2 2026 "Context Constitution" — [Letta blog index](https://www.letta.com/blog)
- Letta Agent File (.af): full agent state export (model config, message history with in-context flags, system prompt, memory blocks, tool rules, env vars, tool source + JSON schema); does **not** yet support Passages (archival memory); roadmap: archival passages, MCP configs, data sources, multi-agent files — [agent-file repo](https://github.com/letta-ai/agent-file)
- MemoryOS (arXiv 2506.06326): short/mid/long-term layers; claims superiority over A-MEM on LoCoMo (self-run); criticizes A-MEM's multi-step link generation for latency and error accumulation; MemoryBench found >17 s per case for construction — [arXiv 2506.06326](https://arxiv.org/pdf/2506.06326); [Benchmark Theatre](https://essays.bloo-mind.ai/posts/2026-05-20-mem-eval/)
- Mastra Observational Memory (Feb 2026): Observer + Reflector background agents; raw messages → dated prioritized observations (token threshold) → reflections (second threshold); each observation carries up to three dates; context prefix is stable/append-only so it is prompt-cacheable (4–10× cost cuts cited); compression 3–6× on text (6× on LongMemEval), anecdotally 5–40× on tool-heavy workloads — [Mastra research](https://mastra.ai/research/observational-memory)
- EverMemOS "self-organizing memory operating system" (Jan 2026) — [arXiv 2601.02163](https://arxiv.org/pdf/2601.02163)

**Agentic memory (A-MEM)**
- A-MEM (NeurIPS 2025): Zettelkasten-style notes with dynamic indexing/linking; LoCoMo with GPT-4o-mini: multi-hop F1 ≈45.9 vs 18.4 baseline (single-hop 27.0 vs 25.0); ~2,520 tokens vs 16,910 for full context ("up to 10× fewer tokens") — [arXiv 2502.12110](https://arxiv.org/pdf/2502.12110); [NeurIPS 2025](https://proceedings.neurips.cc/paper_files/paper/2025/hash/19909c36f51abc4856b4560aff3d36d6-Abstract-Conference.html)

**Structured "world model" / state approaches (closest to ShogunAI)**
- Hindsight: four networks (world facts, agent experiences, synthesized entity summaries, evolving beliefs); retain / recall / reflect; temporal, entity-aware retain layer; reflection updates beliefs traceably; motivation: top-k retrieval "blurs evidence and inference, handles long horizons poorly, and limits explanation"; Memanto rates it "complexity 4 of 4" — [arXiv 2512.12818](https://arxiv.org/abs/2512.12818); [arXiv 2604.22085](https://arxiv.org/pdf/2604.22085)
- Agent Zero Memory (Aug 30 2026): three parallel stores from conversations, files and connected sources — episodic events timeline, entity-event knowledge graph, curated citation-locked Hierarchical Documentary Memory; three concurrent agentic searches merged into one cited answer with a single confidence; every item carries origin, timestamp, evidence pointer; abstains rather than guesses; future work: tombstones for auditable forgetting — [arXiv 2608.29606](https://arxiv.org/pdf/2608.29606)
- Cloudflare Agent Memory (Apr 17 2026, private beta): one Durable Object per memory profile with SQLite store (FTS indexing, supersession chains, transactional writes, raw messages + classified memories) and one Vectorize index per profile; extraction/verification/classification/query analysis by Llama 4 Scout (17B MoE), synthesis by Nemotron 3 (120B MoE); embedding text prepends 3–5 generated search queries; retrieval = five parallel channels (Porter-stemmed FTS, exact fact-key lookup, raw message search, direct vector, HyDE vector) merged by RRF with recency tiebreak; temporal calculations done deterministically, not by the LLM; API `ingest(messages,{sessionId})` (bulk, "typically called at context compaction"), `remember`, `recall` (returns synthesized answer), `forget`, `list`; tested on LoCoMo/LongMemEval/BEAM but no scores published — [Cloudflare blog](https://blog.cloudflare.com/introducing-agent-memory/)
- Supermemory engine: atomic memories from chunks with chunk kept as evidence; relational versioning edges "updates" / "extends" / "derives"; `documentDate` and `eventDate`; working/short/long-term tiers with hot tier on Cloudflare KV; decay — "less relevant information gradually fades"; sub-400 ms latency claim; API `/add`, `/connect`, `/search` plus an "Infinite Chat" proxy — [Supermemory eval report](https://supermemory.ai/research/longmembench); [Supermemory blog Jun 5 2025](https://supermemory.ai/blog/memory-engine)
- Honcho (Plastic Labs): "dialectic reasoning" after conversations maintains a model of user preferences, style, goals; emits user representation + "peer card" + session summary truncated to a `contextTokens` budget — [Hermes Honcho docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/honcho)
- OpenAI ChatGPT memory (Jun 4 2026): new architecture built on "Dreaming" — a background process that synthesizes many conversations without explicit "remember" requests and rewrites a user memory summary (e.g., a planned trip becomes a completed one after the date); users can read/edit the summary and tell ChatGPT when to use it; "memory sources" (GPT-5.5 Instant) show/edit/delete the context used; OpenAI says dreaming had supplemented saved memories for ~a year and "historically was never sufficient as a standalone memory system"; rolled to Plus/Pro US first, Free "soon" thanks to compute efficiency — [Engadget](https://engadget.com/2187811/chatgpt-s-memory-is-getting-better-especially-if-you-re-on-the-free-tier). Mem0's analysis claims ChatGPT does not search past chats or a vector DB at query time but loads a user summary into context each message (vendor interpretation) — [Mem0 on X](https://x.com/mem0ai/article/2071990201531118063)
- Anthropic "dreaming" for Claude Managed Agents (research preview, announced May 6 2026 at Code with Claude; one outlet says May 19): scheduled job between sessions takes one memory store and 1–100 past sessions, extracts patterns, merges duplicates, removes stale entries and writes to a *separate output store* the developer can review or auto-apply; frequency configurable; Harvey reported ~6× task completion in internal testing (vendor-relayed) — [SiliconANGLE](https://siliconangle.com/2026/05/06/anthropic-letting-claude-agents-dream-dont-sleep-job/); [Techzine](https://www.techzine.eu/news/devops/141125/anthropic-introduces-dreaming-for-claude-managed-agents/); [Wikipedia](https://en.wikipedia.org/wiki/Claude_(language_model)). Claude Code's "Auto Dream" consolidation is community-reported from a source leak, not official docs — [Developers Digest](https://www.developersdigest.tech/blog/claude-code-remote-control)
- Governed Shared Memory / MemClaw (Jun 2026): "long-context retrieval alone is insufficient for production multi-agent memory"; scoped retrieval, temporal supersession, provenance tracking, policy-governed propagation — [arXiv 2606.24535](https://arxiv.org/abs/2606.24535)

**"Just use long context + caching"**
- Evidence against: full-context gpt-4o 60.2% vs 80–95% for memory systems on LongMemEval-S; BEAM: 1M-context models degrade with or without RAG; context rot — [Mastra](https://mastra.ai/research/observational-memory); [arXiv 2510.27246](https://arxiv.org/abs/2510.27246); [Chroma](https://www.trychroma.com/research/context-rot)
- Evidence for: with a current reader (GPT-5-mini) long context beat a Mem0-based fact memory on factual recall (Mar 2026); the memory system only wins on cost after ~10 turns at 100K — [arXiv 2603.04814](https://arxiv.org/abs/2603.04814); MemDelta: on GPT-4o-mini, RAG vs full-context is a statistical tie (47.2 vs 49.8) — [arXiv 2606.29914](https://arxiv.org/abs/2606.29914); o4-mini full-context 72.78% ≈ Zep 72.27% (Apr 2025) — [Zep](https://www.getzep.com/blog/gpt-4-1-and-o4-mini-is-openai-overselling-long-context/)
- Anthropic prompt caching (official docs, Oct 2026): 5-min cache writes 1.25× base input, 1-hour writes 2×; reads 0.1× by default, 0.025× on Fable 5.1 / Mythos 5.1, 0.05× on Opus 5.5 / Sonnet 5.5; min cacheable 512 tokens on current models (1,024–4,096 on older); up to 4 breakpoints, 20-block lookback; cache hits don't count against rate limits; e.g., Sonnet 5.5 $2 base / $0.10 hit; Opus 5.5 $4 / $0.20; Fable 5.1 $10 / $0.25; Haiku 5.5 $0.10 / $0.01 (≤100K prompts) — [Anthropic prompt caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)
- Gemini caching: implicit caching on by default for 2.5+ (min prefix 2,048 on 2.5, 4,096 on 3.x/Gemini 4); explicit caching needs ≥32,768 tokens, default 1-hour TTL, storage billed per token-hour — third-party tables list ≈$1.00/M tokens/hour (Flash) and $4.50/M tokens/hour (Pro) with cached reads ≈$0.03–0.20/M; explicit caching not supported in the Interactions API or Gemini 4 Argon+ — [Gemini caching docs](https://ai.google.dev/gemini-api/docs/caching); [fast.io](https://fast.io/resources/gemini-context-caching.md); [morphllm](https://www.morphllm.com/gemini-api-pricing) (verify against Google's price page)
- OpenAI Responses API state: server-stored conversation state via response IDs, or stateless with `store:false` by replaying output including encrypted reasoning items (decrypted in memory per request, discarded); Assistants API sunset Aug 26 2026; long-term cross-session memory is left to the application — [OpenAI conversation state](https://developers.openai.com/api/docs/guides/conversation-state); [OpenAI migrate to Responses](https://developers.openai.com/api/docs/guides/migrate-to-responses); [Mem0 Responses guide](https://mem0.ai/blog/openai-responses-api-and-realtime-agents-with-memory)
- Anthropic context editing + memory tool launch: memory tool + context editing improved performance 39% over baseline; context editing alone 29% (vendor) — [Anthropic announcement](https://www.anthropic.com/news/context-management)

**Latency / cost figures**
- Zep: 155 ms retrieval (vendor 2026) / 189 ms (Mem0's citation); corrected p95 0.632 s vs Mem0 Base 0.200 s (2025) — [Zep research](https://getzep.com/research); [Zep blog](https://www.getzep.com/blog/lies-damn-lies-statistics-is-mem0-really-sota-in-agent-memory/)
- Supermemory sub-400 ms (vendor) — [Supermemory blog](https://supermemory.ai/blog/memory-engine)
- Per-query LLM cost dominates: Agent Zero Memory saw ~30× cost variance across backbones for ~3.4-point accuracy variance — [arXiv 2608.29606](https://arxiv.org/pdf/2608.29606); Mem0 write path ~50× a plain RAG write (MemDelta) — [arXiv 2606.29914](https://arxiv.org/abs/2606.29914)

### Inferences
- The field has converged on a 3-tier, bi-temporal, provenance-carrying design (raw evidence → typed facts/entities with validity windows or `updates`/`extends`/`derives` edges → synthesized summaries/beliefs) plus a background consolidator — structurally ShogunAI's raw events → derived state → summaries + Dream Cycle. Both OpenAI and Anthropic now ship "dreaming" under that name, which validates the concept and commoditizes the vocabulary; ShogunAgent's differentiation is (a) the richness of the derived-state schema (people/projects/commitments/open loops), (b) multi-source ingestion beyond chat, (c) local-first execution, and (d) a deterministic, inspectable state layer rather than an opaque LLM summary.
- Cacheable, stable context prefixes (Mastra OM; ChatGPT's per-message summary) combined with 0.025–0.1× cache-read pricing make a "profile + current state block" injected every turn nearly free; ShogunAgent should expose a deterministic, append-only "context block" API rather than per-turn ad-hoc retrieval, and do temporal math deterministically (Cloudflare's choice) rather than via the LLM.
- Graph *engines* are losing favor (Mem0 removed traversable relations; Kuzu deprecated in Graphiti; Zep dropped self-hosting) while graph *semantics* (typed, time-bounded relations, supersession chains) are universal; an entity/state table with typed relation rows in SQLite/Postgres captures most of the value with far less operational cost.
- Current-generation readers narrow the gap with long context on pure recall; the durable case for a memory layer is cost after ~10 turns, latency, cross-session/cross-source state, deletion/provenance, and the categories (temporal, multi-session, knowledge updates) where structure helps — ShogunAgent's positioning should lean on those, not on "beats long context on recall."

### Gaps
- No same-harness latency or $/query comparison across architectures; only tokens per answer.
- No published head-to-head between an explicit entity/state-table world model (like ShogunAI's) and graph/vector systems on any standard benchmark.
- OpenAI has not published ChatGPT memory architecture details; the "no vector search at query time" claim is Mem0's interpretation.
- Anthropic's primary dreaming announcement page was not retrieved; details come from press coverage.

## Key Question 3: Research papers 2025–2026 — consolidation, forgetting, multi-agent, portability, provenance, user models

### Takeaway
2026 research has moved from "how to retrieve" to "how memory should change over time": offline/sleep consolidation is now mainstream (Letta sleep-time, Auto-Dreamer, MemDream, SCM, LightMem, SleepGate, "Language Models Need Sleep"), provenance and governed sharing are formalized for multi-agent fleets (MemClaw, MAP-Graph), a lifecycle security framework (EMNLP 2026) finds lineage tracking through compression/reflection is rare so deletions rarely propagate, and user-preference inference remains weak (CUPID: precision <50%, recall <65%). Heterogeneous forgetting and "authority-conditioned mutability" are the named open problems — all mapping onto ShogunAI's Dream Cycle and world-model provenance.

### Cited Findings

**Consolidation / "sleep" / "dream" cycles**
- Letta sleep-time compute (Apr 2025): background agent rewrites in-context memory during idle time; "Pareto improvement" shifting compute from latency-critical turns to idle periods — [Letta blog](https://www.letta.com/blog/sleep-time-compute)
- Auto-Dreamer (arXiv May 20 2026): a *learned* offline consolidator; argues existing systems couple acquisition and consolidation into one online process; trained only on ScienceWorld, beats fixed, RL-trained and prompted memory baselines by 7 points and transfers to ALFWorld and WebArena without retraining — [arXiv 2605.20616](https://arxiv.org/abs/2605.20616)
- MemDream (Sep 2026): asynchronous "dream cycles" with three agents — Dreamer probes the memory graph with forward-looking queries, Analyst finds retrieval failures, Consolidator repairs the graph — while the agent keeps answering — [arXiv 2609.34545](https://arxiv.org/html/2609.34545v1)
- SCM "Sleep-Consolidated Memory" (Apr 2026, research preview): limited-capacity working memory, importance tagging, NREM/REM-style offline consolidation, value-based forgetting, self-model; reports perfect recall over ten-turn conversations and a 90.9% cut in memory noise (self-reported) — [arXiv 2604.20943](https://arxiv.org/pdf/2604.20943)
- LightMem (ICLR 2026): sleep-time update decouples consolidation from online inference; reports QA accuracy and token/API-call savings on LongMemEval and LoCoMo — [DEV overview](https://dev.to/izgorodin/what-is-memory-consolidation-in-long-term-ai-memory-systems-2j8e)
- SleepGate (Mar 2026): periodic sleep micro-cycles over the KV cache evict stale entries and merge the rest — [arXiv 2603.14517](https://arxiv.org/html/2603.14517v1); "Language Models Need Sleep" (May 2026): consolidated context written into fast weights of state-space layers — [alphaxiv 2605.26099](https://www.alphaxiv.org/abs/2605.26099v1); "Human-Inspired Memory Architecture" (May 2026) with sleep-phase consolidation — [emergentmind 2605.08538](https://www.emergentmind.com/papers/2605.08538)
- "The Sleeping Agent: What Gist-Based Context Compression Loses and Why" (Aug 2026) — a caution on what summarization-style consolidation destroys — [arXiv 2608.11775](https://arxiv.org/pdf/2608.11775)
- Commercial: OpenAI "Dreaming" (Jun 2026), Anthropic Managed Agents "dreaming" (May 2026), Mastra Reflector, Hindsight "reflect" — see KQ2.

**Forgetting / decay**
- "Always-On Agents" survey (Jun 2026): most work decays uniformly whereas real state is heterogeneous; "authority-conditioned mutability" is open — [arXiv 2606.30306](https://arxiv.org/pdf/2606.30306)
- "Memory for Autonomous LLM Agents" survey (Mar 2026): open challenges — continual consolidation, causally grounded retrieval, trustworthy re-reflection, learned forgetting — [arXiv 2603.07670](https://arxiv.org/pdf/2603.07670v1)
- FSFM: biologically inspired selective forgetting (Apr 2026) — [arXiv 2604.20300](https://arxiv.org/pdf/2604.20300); Oblivion: decay-driven activation for agentic memory control (Apr 2026) — arXiv 2604.00131; STALE: can agents tell when memories are no longer valid (May 2026) — arXiv 2605.06527 (both cited via [search](https://arxiv.org/html/2604.16548v1); IDs not independently opened)
- MemoryAgentBench treats selective forgetting as a core competency current methods fail — [arXiv 2507.05257](https://arxiv.org/abs/2507.05257)

**Multi-agent memory and governance**
- Governed Shared Memory (Margalit et al., Jun 23 2026): four failure modes — unauthorized leakage, stale propagation, contradiction persistence, provenance collapse; MemClaw multi-tenant service + ArgusFleet harness; 100% of depth-four derivation chains reconstructed with correct writer identity; zero cross-fleet leakage; production bugs found: sub-tenant scope bypass on GET-by-id, and a synchronous near-duplicate gate rejecting contradictory writes before the async contradiction detector ran; "provenance tracking was the cleanest positive result" — [arXiv 2606.24535](https://arxiv.org/abs/2606.24535)
- MAP-Graph (Aug 2026): provenance-aware shared memory pairing semantic relevance with permission filtering and action-time gating; 0% observed leakage and revocation violations on a controlled benchmark; cross-session/deployment-scale testing is future work — [arXiv 2608.10509](https://arxiv.org/pdf/2608.10509)
- "Beyond Memory Majority: Latent-Source Reasoning for Multi-Agent Memory Arbitration" (Aug 2026) — [arXiv 2608.19701](https://arxiv.org/pdf/2608.19701); "The Song, Not the Pin" (NeurIPS 2026): shared memory needs explicit provenance, time-bounded validity and revocable coordination authority — [NeurIPS 2026](https://neurips.cc/virtual/2026/169580)
- Claude Code subagents can keep separate auto-memory directories; main memory is not loaded into subagents except forks — [Claude Code docs](https://code.claude.com/docs/en/memory)

**Provenance**
- Agent Zero Memory: origin, timestamp, evidence pointer on every item; answers limited to evidence the reader opened — [arXiv 2608.29606](https://arxiv.org/pdf/2608.29606); Eywa "provenance-grounded long-term memory" (May 2026) — [arXiv 2605.30771](https://arxiv.org/pdf/2605.30771); MemChain: interpretable memory traces (Jul 2026) — [arXiv 2607.24097](https://arxiv.org/pdf/2607.24097)
- Security survey (Lin et al., Apr 17 2026, v3 Sep 22 2026, accepted EMNLP 2026): Memory Lifecycle Framework with six phases (Write, Store, Retrieve, Execute, Share & Propagate, Forget & Rollback) × four objectives (Integrity, Confidentiality, Availability, Governance); "Verifiable Memory Governance" with five primitives anchored in storage-time provenance, versioning and policy-aware retention; finds lineage tracking through compression and reflection is rare, so deletion rarely propagates to derived entries — [arXiv 2604.16548](https://arxiv.org/html/2604.16548v1)
- Supermemory keeps the source chunk attached to each atomic memory — [Supermemory](https://supermemory.ai/research/longmembench)

**Portability / agent-file formats**
- Letta .af (Apr 2025): exports model config, full message history with in-context flags, system prompt, memory blocks, tool rules, env vars, tool code + schema; no Passages (archival memory) yet; community uses it as "a declaration, not a transcript: zero messages, blanked secrets" — [agent-file repo](https://github.com/letta-ai/agent-file); [Letta blog](https://www.letta.com/blog/agent-file/)
- Letta Context Repositories make memory a git repo (versioned, mergeable, portable) — [Letta blog](https://www.letta.com/blog/context-repositories)
- Anthropic Claude memory import/export (~Mar 1 2026, third-party reports): prompted export from another assistant pasted into Claude's import tool — [TechCabal](https://techcabal.com/2026/05/27/4-easy-steps-to-move-your-chatgpt-memory-to-claude/)
- Claude Code auto memory is plain markdown (`MEMORY.md` + topic files), user-editable and relocatable — [Claude Code docs](https://code.claude.com/docs/en/memory)

**Personal user-model inference**
- CUPID (COLM 2025): can LLMs infer contextual user preferences from prior sessions? Across 10 models precision <50% and recall <65%; explicit session-summary memory helped smaller models but had little or negative effect on larger ones — [arXiv 2508.01674](https://arxiv.org/pdf/2508.01674)

- Honcho dialectic reasoning (user representation + peer card), Mastra Observer (current task + priorities), Mem0 (agent-generated facts beside user facts) — [Hermes Honcho README](https://download.hermesedi.duckdns.org/.hermes/hermes-agent/plugins/memory/honcho/README.md); [Mastra](https://mastra.ai/research/observational-memory); [Mem0](https://mem0.ai/blog/state-of-ai-agent-memory-2026)

**Other notable 2026 systems/papers**
- MemReader (Apr 2026) — [arXiv 2604.07877](https://arxiv.org/pdf/2604.07877); Memanto typed semantic memory (Apr 2026) — [arXiv 2604.22085](https://arxiv.org/pdf/2604.22085); ZenBrain 7-layer (Apr 2026; notes public LongMemEval scores use "full-context consolidation with task-tuned prompts" and aren't comparable to k=5 reruns) — [arXiv 2604.23878](https://arxiv.org/pdf/2604.23878); H-Mem hybrid structure (May 2026) — [arXiv 2605.15701](https://arxiv.org/pdf/2605.15701); Agentic Context Management (Jul 2026) — [arXiv 2607.21503](https://arxiv.org/pdf/2607.21503); "Memory as Metabolism" (Apr 2026) — [arXiv 2604.12034](https://arxiv.org/pdf/2604.12034); "Continual Learning in Transition" (Aug 2026) — [arXiv 2608.06216](https://arxiv.org/pdf/2608.06216); "Cost and Accuracy of Long-Term Memory in Distributed Multi-Agent Systems" (Jan 2026) — [arXiv 2601.07978](https://arxiv.org/html/2601.07978v5)

### Inferences
- ShogunAI's Dream Cycle has strong academic and now frontier-lab precedent; "dreaming" as a term is being commoditized by OpenAI and Anthropic. The research-grade differentiators available to ShogunAgent are *heterogeneous decay by state type* (commitments vs preferences vs ephemeral screen context), *authority-conditioned mutability* (who/what may overwrite a fact), a learned/verified consolidator (Auto-Dreamer, MemDream style self-probing), and lineage that survives consolidation so deletions propagate (the EMNLP survey's identified gap).
- MemClaw's production bugs (scope bypass on GET-by-id; sync dedup beating async contradiction detection) and MAP-Graph's revocation tests are concrete test cases for ShogunAgent's harness.
- User-model inference is empirically weak (CUPID), which argues for ShogunAgent's approach of deriving state from *observed events* (calendar, email, screen) rather than inferring preferences from chat alone, and for exposing confidence/provenance on every inferred attribute.
- A `.af`-like export plus git-backed, file-shaped memory are now expected; ShogunAgent should ship an open export schema (entities, facts with validity intervals, provenance pointers, tombstones) from day one.

### Gaps
- No peer-reviewed quantification of how much consolidation improves downstream accuracy vs cost in production agents beyond Auto-Dreamer's +7 points (ScienceWorld) and Mastra's compression ratios; Harvey's 6× is vendor-relayed.
- No standard agent-memory portability format beyond Letta's .af; no cross-vendor adoption evidence.
- Oblivion / STALE / TRUSTMEM / RecMem were seen only in reference lists; IDs not verified.

## Key Question 4: Privacy and security

### Takeaway
Memory poisoning is a demonstrated, peer-reviewed attack class (MINJA via ordinary queries; OWASP ASI06 "Memory and Context Poisoning" in the Dec 2025 Agentic Top 10), though a Jan 2026 follow-up found MINJA's >95% injection rate holds only under idealized conditions and pre-existing legitimate memories "dramatically reduce" effectiveness; 2026 defenses center on write-path trust scoring, provenance/lineage, consensus validation, signed/certified memory and human review gates. On regulation, no DPA has issued agent-memory-specific guidance, GDPR Art. 17 erasure against embeddings/consolidated memories is widely called unsolved (vector DBs are append-only; derived entries lack lineage), and EU AI Act high-risk obligations take effect Aug 2026 — collectively favoring ShogunAgent's local-first, provenance-linked, cascade-deletable design. No commercial memory vendor was found offering user-held-key encryption; AWS AgentCore offers customer-managed KMS keys.

### Cited Findings

**Attacks**
- MINJA (Dong et al.; arXiv 2503.03704; NeurIPS 2025 / revised Feb 2026): injects malicious records only via queries and output observations using "bridging steps", an "indication prompt" and "progressive shortening"; original work reports >95% injection success and 70% attack success — [arXiv 2503.03704](https://arxiv.org/abs/2503.03704); [NeurIPS 2025](https://neurips.cc/virtual/2025/poster/118152)
- "Memory Poisoning Attack and Defense on Memory Based LLM-Agents" (arXiv Jan 9 2026): MINJA's figures hold "only under idealized conditions"; on MIMIC-III EHR agents with GPT-4o-mini, Gemini-2.0-Flash and Llama-3.1-8B, "realistic conditions with pre-existing legitimate memories dramatically reduce attack effectiveness"; defenses — composite trust scoring on input/output, and trust-aware retrieval with temporal decay and pattern filtering; thresholds are fragile (too strict blocks everything, too loose misses subtle attacks) — [arXiv 2601.05504](https://arxiv.org/abs/2601.05504)
- 2026 variants: sleeper memory poisoning (arXiv 2605.15338); MemoryGraft (poisoned experience retrieval); "Benign Alone, Harmful Together: Exploiting Experience Composition in Self-Evolving Agents" — [arXiv 2608.01759](https://arxiv.org/pdf/2608.01759); systematic study of memory poisoning (arXiv 2606.04329); "Injection-Execution Dissociation" mechanistic evaluation — [arXiv 2605.08442](https://arxiv.org/pdf/2605.08442) (IDs from [search](https://www.alphaxiv.org/abs/2601.05504), not all opened)
- A-MemGuard cites: LLM-based detectors miss 66% of poisoned entries because they look harmless in isolation — [arXiv 2510.02373](https://arxiv.org/html/2510.02373v1); Mem0's security blog repeats the 66% figure — [Mem0 security](https://mem0.ai/blog/ai-memory-security-best-practices)
- OWASP Top 10 for Agentic Applications 2026 (canonical list published Dec 9 2025): ASI06 "Memory and Context Poisoning" — attacker writes to durable stores (RAG indexes, vector DBs, history) and the agent acts on it later; "by the time a poisoned memory is retrieved and folded into context, it isn't untrusted input anymore," so input/output prompt-injection filters miss it; suggested mitigations: content provenance, immutability for agent memory, recency bias against suspicious context, human-review gates for high-stakes memory writes, detection on the write path — [vectorize.io ASI06](https://vectorize.io/articles/owasp-asi06); [Zealynx](https://www.zealynx.io/blogs/owasp-asi06-memory-context-poisoning); [trackr](https://www.trackr.live/?p=1223) (official OWASP page not retrieved)

**Defenses**
- A-MemGuard (Oct 2025): consensus-based validation + dual-memory "lessons" store; claims >95% cut in attack success — [arXiv 2510.02373](https://arxiv.org/html/2510.02373v1)
- SMSR: certified defense against runtime memory poisoning via signed memory (Jun 2026) — [arXiv 2606.12703](https://arxiv.org/pdf/2606.12703); MemLineage: lineage-guided enforcement (May 2026) — arXiv 2605.14421; "An Empirical Study of Memory Poisoning Defenses" — [ICML 2026](https://icml.cc/virtual/2026/poster/61006)
- SuperLocalMemory (Mar 2026): privacy-preserving local multi-agent memory with Bayesian trust defense; notes Mem0's local option needs Docker + PostgreSQL + Qdrant — [arXiv 2603.02240](https://arxiv.org/pdf/2603.02240)
- OWASP Agent Memory Guard (reported Jun 1 2026): runtime layer screening every read/write; 92.5% recall at 59 µs (secondary, unverified) — [feedbagel](https://feedbagel.com/post/owasp-agent-memory-guard-stop-ai-agents-from-being-weaponized-through-their-own-)
- Security lifecycle survey (EMNLP 2026): security "can't be added only at retrieval or execution time"; must be anchored in storage-time provenance, versioning, policy-aware retention — [arXiv 2604.16548](https://arxiv.org/html/2604.16548v1)
- MemClaw governance primitives; scope bypass found and fixed in production — [arXiv 2606.24535](https://arxiv.org/abs/2606.24535)

**Vendor security guidance and practice**
- Anthropic memory tool: client-side ("you control where and how the data is stored"); handler must reject paths outside `/memories` (e.g., `/memories/../../secrets.env`, `%2e%2e%2f`); "Claude usually refuses to write sensitive information to memory files. - AWS Bedrock AgentCore Memory: encrypted by default with AWS-managed keys, optional customer-managed KMS keys; short-term retention configurable up to 365 days (time-limited, not zero retention) — [DEV / AWS Heroes](https://dev.to/aws-heroes/amazon-bedrock-agentcore-runtime-part-6-using-agentcore-short-term-memory-with-strands-agents-sdk-55d4)

**Regulation**
- GDPR Art. 17 interpretations: erasure must reach graph nodes/edges, vector embeddings, cached recall results, backups/replicas (Cognee, vendor) — [Cognee](https://www.cognee.ai/gdpr-compliant-ai-memory-platform); many vector DBs are append-only/copy-on-write so "deleted" records persist until compaction; snapshots and caches too — [sota.io](https://sota.io/blog/eu-ai-act-agentic-ai-memory-rag-compliance-gdpr-vector-stores-2026); "no commercially available vector database provides a provable deletion mechanism"; recommend per-user namespaces and embedding-ID → source mapping for cascading deletes — [tianpan.co Apr 10 2026](https://tianpan.co/blog/2026-04-10-gdpr-ai-agents-compliance-architecture)
- Academic (SAGE, 2026): "case law has not directly addressed the application of the rights to erasure and to be forgotten in relation to AI systems, although the first proceedings are beginning to emerge before European DPAs" — [Fernández Delgado & Cazurro Barahona](https://journals.sagepub.com/doi/10.1177/18479790261468434); 2026 review: GDPR "not written around LLM-agent architectures"; open question of a legal basis for purpose-unspecified persistent memory — [arXiv 2609.22712](https://arxiv.org/pdf/2609.22712)
- CNIL guidance on agent-based AI: persistent memory enables hyper-personalization but raises outdated/inaccurate-data risk — [TrustArc](https://trustarc.com/products/privacy-data-governance/nymity-research/france-cnil-agent-based-ai-guidance/); Mar 2025: 32 European DPAs launched a coordinated deletion investigation — [DEV](https://dev.to/manav8498/your-ai-agent-remembers-everything-can-it-prove-it-forgot-3l79)
- EU AI Act: high-risk obligations / logging enforceable Aug 2 2026 (secondary; one source claims 10-year log retention, conflicting with others; "Digital Omnibus" changes unverified); AI Act traceability duties pull against GDPR erasure — [sota.io](https://sota.io/blog/eu-ai-act-agentic-ai-memory-rag-compliance-gdpr-vector-stores-2026); [techgdpr](https://techgdpr.com/blog/reconciling-the-regulatory-clock/) — verify against Regulation 2024/1689

### Inferences
- A derived-state design where every fact carries a provenance pointer to its raw event enables the cascade deletion regulators want (delete raw event → invalidate derived facts → regenerate summaries) and the lineage the EMNLP survey says is missing; embeddings-only systems cannot offer this. It is a concrete compliance advantage ShogunAgent can market, provided consolidation preserves lineage and tombstones.
- Screen-text ingestion captures third parties' personal data (colleagues' names, emails), so ShogunAgent needs per-source consent/retention policies and redaction *before* consolidation, plus an "exclusion rules" API like Mem0's.
- Memory-write validation (trust scoring, source-authority tagging, consensus checks, write-path logging, optional human review for high-stakes writes) should be a core API feature; the realistic-conditions finding (legitimate memories dilute attacks) also suggests that a dense, provenance-weighted world model is itself a mitigation.
- User-held-key encryption is an open market niche: no commercial memory vendor was found offering it; AWS offers CMK only.

### Gaps
- Official OWASP ASI06 text and Agent Memory Guard page not retrieved; figures are secondhand.
- No source on how Zep, Letta or Supermemory implement encryption at rest, key management, or zero-retention; no commercial memory vendor found offering client-side/user-held-key encryption.
- No primary legal text verified for AI Act dates/retention; no DPA decision specific to agent memory found.

## Key Question 5: Implementation stack

### Takeaway
The pragmatic 2026 stack for a local-first Rust memory service is SQLite (+FTS5) with sqlite-vec or LanceDB for vectors, an entity/relation table instead of a graph engine (Kuzu was archived Oct 2025; its MIT-licensed revival LadybugDB ships a Rust crate `lbug` with Cypher, FTS and vector index, but Graphiti has deprecated Kuzu support and FalkorDB/Neo4j are server-based), local embeddings via fastembed-rs/ONNX (Qwen3-Embedding 0.6B/4B, nomic) with hosted fallbacks (OpenAI text-embedding-3-large ~$0.13/MTok, Voyage ~$0.12/MTok), and for a hosted tier either pgvector with RLS on existing Postgres (<~5M vectors) or namespace-per-tenant object-storage vector stores (Turbopuffer) or Cloudflare Durable Objects + Vectorize (the design both supermemory and Cloudflare Agent Memory chose). LLM extraction/consolidation tokens, not vector storage, dominate cost per 1M memories.

### Inferences
- For 1M memories (≈1M vectors at 1024 dims), infra cost is dominated by plan minimums, not storage (Turbopuffer ≈ $0.30 storage + $16–64 minimum; pgvector on existing Postgres ≈ $50/mo; a single-user local SQLite file is free). LLM extraction/consolidation tokens are the real cost driver — Mem0's ~7K tokens/retrieval, Hindsight's ~25K, Mem0's ~50× write-path premium over plain RAG, and Agent Zero's 30× backbone cost spread all show that; ShogunAgent's cost model should be quoted per *ingested event* and per *dream cycle*, not per vector.
- Given Kuzu's death and Mem0's retreat from graph traversal, model relations as typed rows (subject, predicate, object, valid_from, valid_to, provenance, confidence) in SQLite/Postgres with recursive CTEs; keep LadybugDB (`lbug`) as an optional embedded Cypher layer only if traversal depth demands it.
- A Durable-Object-per-user design (Cloudflare Agent Memory, supermemory) matches ShogunAgent's "one user = one world model" shape and gives natural isolation; the hard part is sync from a local-first Rust core to an edge object — supermemory's SMFS and Letta's git-backed MemFS show a filesystem/git-shaped sync surface is viable and agent-friendly.
- Run a local embedding by default (fastembed-rs + Qwen3-Embedding-0.6B or nomic) for privacy and egress; pin the embedding model per benchmark run and across tenants to avoid MemDelta-style confounds; Cloudflare's trick of prepending generated search queries to embedded text is cheap and portable.

- LadybugDB maturity/adoption beyond crate listings is unverified; Apple-acquisition detail rests on two weak sources.

## Key Question 6: Interfaces — what agents actually call

### Takeaway
Three interface shapes dominate in October 2026: (1) file-shaped memory — Anthropic's `memory_20250818` tool (view/create/str_replace/insert/delete/rename under `/memories`, client-side storage, auto-injected "always view memory first; assume interruption" protocol), Claude Code's `MEMORY.md` index (200 lines / 25KB budget) and Letta's git-backed MemFS; (2) verb-shaped memory APIs — MCP servers converging on add/search/update/delete with no standard names (three popular servers each ship an `add_memory` that does different things), Cloudflare's `ingest / remember / recall / forget / list`, supermemory's `/add /connect /search`, and OpenAI leaving memory to the app above a stateless Responses API; (3) budgeted context injection — Honcho's `contextTokens`, Mastra's cacheable observation log, ChatGPT's per-message editable summary, and Cloudflare's `ingest` called at compaction time. ShogunAgent should support all three: a virtual filesystem view, MCP add/search tools, and a budgeted `get_context`/profile endpoint, with agent-scratch namespaces separated from the user world model.

### Inferences
- The de-facto lowest common denominator across Anthropic, Letta (git MemFS), Supermemory SMFS and Claude Code is a *filesystem of markdown/text files with an index file*. ShogunAgent can expose derived state as a virtual filesystem (`/memories/people/<name>.md`, `/memories/projects/<id>.md`, `/memories/open_loops.md`, `/memories/INDEX.md`) and work with the Anthropic memory tool with zero custom integration, while MCP `add_memory`/`search_memory` and a budgeted `get_context(profile, max_tokens)` serve retrieval-centric agents. Mirroring Cloudflare's verb set (recall/remember/forget/list) plus `ingest` at compaction time covers the remaining idiom.
- An index capped at ~200 lines / 25KB (Claude Code) is a useful design constraint: ShogunAgent's profile/summary tier should fit that budget with detail in on-demand topic files, and should be stable/append-ordered to maximize prompt-cache hits.
- Because the Anthropic API injects an "assume interruption, write progress to memory" protocol, agents will write *task state* constantly; ShogunAgent must separate agent-scratch namespaces from user world-model facts (authority-conditioned mutability) so agent notes cannot pollute or poison the user model, and should log every write with actor/provenance (also the ASI06 mitigation).
- With OpenAI offering no long-term memory API and the Assistants API gone, the "memory layer above a stateless Responses API" is an explicit market gap that Mem0, Zep, supermemory and Cloudflare are all targeting; ShogunAgent's wedge is the observed-world state, not chat memory.

### Gaps
- No formal MCP specification or community standard for memory tools exists; naming varies per server.
- No source on streaming / server-pushed context injection mid-turn ("context budget" APIs beyond Honcho's `contextTokens`).
- OpenAI ChatGPT memory internals remain unpublished; the "summary loaded every message" description is a vendor's inference.
