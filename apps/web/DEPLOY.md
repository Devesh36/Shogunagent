# Deploying shogunagent.com

Runbook for putting `apps/web` on the registered domain `shogunagent.com`. Written so an operator or a coding agent (Codex) can do it end to end. Nothing here needs a change to the site's code.

## What you are deploying

- A Cloudflare Worker named `shogunagent-web` (`apps/web/wrangler.jsonc`) that serves the static files in `apps/web/dist/` and does content negotiation (`src/worker.js`).
- `dist/` is generated by `pnpm --filter @shogun-ai/web build` from `content/site.json`. It is not committed. Build before every deploy; `pnpm --filter @shogun-ai/web deploy` does both.
- No database, no secrets, no environment variables. The Worker reads no request body and keeps no state.

Reserved and out of scope here: `api.shogunagent.com` belongs to `apps/api` (Phase 1). Do not route it to this Worker.

## Prerequisites

1. A Cloudflare account on the Workers Paid plan (custom domains on Workers need a paid plan; the free plan also works if `custom_domain` routes are supported on your account, but Paid avoids surprises).
2. The `shogunagent.com` zone added to that Cloudflare account, with the registrar's nameservers switched to the two Cloudflare nameservers the zone page shows. Wait until the zone status is **Active**.
3. Wrangler authenticated: `pnpm --filter @shogun-ai/web exec wrangler login`, or set `CLOUDFLARE_API_TOKEN` (token with **Workers Scripts: Edit**, **Workers Routes: Edit**, **Zone: Read**, **DNS: Edit** on the `shogunagent.com` zone) and `CLOUDFLARE_ACCOUNT_ID`. Never commit either value.
4. Node 22 and pnpm 10 (`corepack enable` picks the version pinned in the root `package.json`).

## Steps

```sh
# from the repository root
pnpm install
pnpm --filter @shogun-ai/web test        # must print "# fail 0"
pnpm --filter @shogun-ai/web build       # writes apps/web/dist
pnpm --filter @shogun-ai/web run deploy  # builds again, then `wrangler deploy --config apps/web/wrangler.jsonc`
```

On the first deploy Wrangler creates the Worker, uploads `dist/` as static assets, and attaches the two custom domains in `wrangler.jsonc` (`shogunagent.com` and `www.shogunagent.com`). Custom domains create their own DNS records and TLS certificates; do not add A/AAAA/CNAME records for these two names by hand. If a record already exists for the apex or `www`, delete it first or Wrangler reports a conflict.

## Verify

Every check below must pass before you call it done.

```sh
# HTML for a browser
curl -sI https://shogunagent.com/ | grep -i -E '^(HTTP|content-type|link|content-signal)'
#   HTTP/2 200, content-type: text/html; charset=utf-8,
#   link: <https://shogunagent.com/llms.txt>; rel="alternate"; type="text/plain", <https://shogunagent.com/index.md>; rel="alternate"; type="text/markdown"
#   content-signal: ai-train=yes, search=yes, ai-input=yes

# Markdown for an agent (same URL)
curl -s -H 'Accept: text/markdown' https://shogunagent.com/ | head -3
#   # ShogunAgent
#   (blank)
#   > The state layer for AI agents. Memory remembers. State knows.
curl -sI -H 'Accept: text/markdown' https://shogunagent.com/ | grep -i -E 'content-type|content-location'
#   content-type: text/markdown; charset=utf-8
#   content-location: https://shogunagent.com/index.md

# The agent documents
for p in llms.txt llms-full.txt index.md setup-prompt.txt robots.txt sitemap.xml; do
  printf '%-18s ' "$p"; curl -s -o /dev/null -w '%{http_code} %{content_type}\n' "https://shogunagent.com/$p"
done
#   all 200; .txt and .md are text/plain or text/markdown with charset=utf-8

# www and http redirect to the apex over https (Cloudflare "Always Use HTTPS" should be on in the zone's SSL/TLS settings)
curl -sI http://www.shogunagent.com/ | grep -i -E '^(HTTP|location)'
```

Also open `https://shogunagent.com/?agent=1` in a browser: the page should show the Markdown view.

## Zone settings worth setting once

In the Cloudflare dashboard for the `shogunagent.com` zone:

- SSL/TLS: encryption mode **Full (strict)**; **Always Use HTTPS** on; **Automatic HTTPS Rewrites** on; minimum TLS 1.2.
- Speed: **Brotli** on. Leave Rocket Loader, Auto Minify and Email Obfuscation **off** (they rewrite HTML and would break the "HTML and Markdown are generated from one source" guarantee and the inline copy button).
- Caching: default. The Worker already sets `Vary: Accept`, so cached HTML is never served to a client that asked for Markdown.
- Do **not** enable Cloudflare Web Analytics or any bot-blocking rule that challenges non-browser user agents: agents are the audience, and `robots.txt` says so (`Content-Signal: ai-train=yes, search=yes, ai-input=yes`). If "Bot Fight Mode" or "AI Scrapers and Crawlers" blocking is on, turn it off for this zone.

## Rolling back

`wrangler rollback --config apps/web/wrangler.jsonc` (or pick a previous version in the dashboard under the Worker's **Deployments**). Content changes are made in `content/site.json`, tested, built and redeployed; there is nothing else to roll back.

## What not to do

- Do not edit anything in `dist/`; it is overwritten on build.
- Do not mark a hosted surface `live` in `content/site.json` until it answers on `api.shogunagent.com`; a test rejects it.
- Do not add analytics, a cookie banner, or a third-party script. There is nothing to consent to because nothing is collected.
- Do not put `api.shogunagent.com`, a database binding, or any secret into `apps/web/wrangler.jsonc`.
